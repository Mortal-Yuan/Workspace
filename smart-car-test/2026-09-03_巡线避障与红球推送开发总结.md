# 2026-09-03 巡线、避障与红球推送开发总结

## 1. 今日目标与最终结果

今天围绕三轮全向小车完成了四条主线：恢复并稳定巡线/避障基线、加入固定入场动作、完善红蓝目标视觉与调试工具、实现独立的红球入夹和推入蓝色目标区域状态机。

当前烧录到小车中的最终版本具有以下行为：

1. `BOOT` 或串口 `f`：先等待超声波确认前方安全，再执行固定入场动作，之后进入 9 月 1 日版本的巡线和定时避障流程。
2. 调试窗口按钮或串口 `b`：从 `IDLE` 单独启动红球任务；先找红球，同时记住最早稳定看到的任意蓝色目标，随后完成路线横移、红球对齐、分段接近、入夹确认、目标横移对齐和推球。
3. 串口 `x` 或调试窗口红色急停按钮：立即停止并退出当前运动模式。
4. 球任务中的视觉丢失和超时不再永久锁存 `BALL_FAILSAFE`，而是立即停车、等待 2 秒，在摄像头恢复后重新开始找球。

最终固件已经完成主机回归、ESP-IDF 完整构建、COM3 烧录、三段 Flash 独立回读校验和无运动启动检查。调试窗口已恢复运行。

## 2. 巡线与固定入场动作

### 2.1 恢复 9 月 1 日巡线基线

巡线核心已恢复为本地 Git 提交 `9354358` 中的 9.1 逻辑，避免后续试验中的错误左右判断和不可靠搜索行为继续影响主线：

- 图像巡线输入为摄像头下半幅中央 ROI。
- 方向权重为 `L/LC/RC/R = -6/-2/+2/+6`。
- 巡线修正公式为 `correction = clamp(error * 120, -300, 300)`。
- 正常直线速度为 348，普通弯道为 276，单侧边缘为 233。
- 丢线先保留最后一次可靠运动 120 ms，随后停车至 150 ms，再按最近方向左右扩展搜索。
- 丢线搜索速度为 211，搜索段依次扩展为 1.2、2.4、3.6、4.8、6.0 和 7.2 秒；重新识别需要 3 个新画面。

### 2.2 固定入场动作

为绕过第一个难以通过的右弯，新增 `startup_maneuver.c/.h`，每次启动自动巡线时执行一次：

| 阶段 | 当前参数 |
| --- | --- |
| 前进启动助力 | 500，持续 150 ms |
| 前进稳态 | 400，总前进时间 1074 ms，约 20 cm |
| 前进后停车 | 150 ms |
| 顺时针原地转动 | 420，持续 200 ms，开环估计约 60° |
| 转动后停车 | 150 ms |
| 后续 | 清空巡线方向历史，进入摄像头巡线 |

右转时间经历了 400 ms → 267 ms → 200 ms 的现场调整；当前 200 ms 是上一版的四分之三。该角度仍是开环时间估计，没有陀螺仪闭环。

## 3. 避障流程优化

当前避障采用固定分段路径，超声波首次得到 20～80 mm 的真实近距离 Echo 时立即制动：

```text
SENSOR_CHECK -> CLEAR -> BRAKE
-> LEFT_STRAFE -> SETTLE_FORWARD -> FORWARD_TIMED
-> SETTLE_RIGHT -> RIGHT_RAMP -> FINAL_FORWARD -> FINISHED
```

主要参数如下：

| 参数 | 当前值 |
| --- | ---: |
| 触发距离 | 80 mm |
| 制动 | 150 ms |
| 左横移 | 380，启动 500/150 ms，共 1030 ms |
| 中段前进 | 400，启动 500/150 ms，共 1074 ms |
| 右横移 | 300 → 380，在 400 ms 内线性提升 |
| 右横移启动反偏航 | -60 → 0，在同一 400 ms 内衰减 |
| 右横移总时间 | 1097 ms |
| 最后直行 | 525 ms |

右横移使用渐增速度和短暂逆向偏航补偿，减少起步瞬间的顺时针偏转；避障开始后摄像头线形不能提前截断固定路径，最后直行结束后进入锁存 `FINISHED`。

## 4. 摄像头与实时调试工具

### 4.1 当前图像链路

- UVC 摄像头输入：640×480 MJPEG，15 FPS。
- JPEG 解码：`1/8` 缩放到 80×60。
- 红球和蓝色区域：分析完整 80×60 画面，不受巡线 ROI 限制。
- 巡线：分析 80×30 下半幅，再应用中央 ROI。
- 摄像头新鲜度门限：350 ms。

今天曾测试完整 640×480 和折中 320×240 识别，但实测约为 1 FPS 和 2.2～2.6 FPS，控制响应过慢；最终完整回退到与距离标定一致的 80×60 管线。

### 4.2 USB-UART 调试窗口

新增 `camera_preview.c/.h` 和 `tools/usb_camera_monitor.py`：

- 串口 `u` 从 115200 协商到 460800 bit/s，传输带 CRC32 的 80×60 RGB332 预览。
- 串口 `z` 或 3 秒心跳超时恢复到 115200 bit/s。
- 窗口显示巡线 ROI、黑色分割、近/远线中心、红球、两个蓝色候选、状态机、电机指令和传感器遥测。
- 红球候选使用橙框，确认红球使用洋红框；两个蓝色检测槽使用不同青色标记。
- 提供“找球并推入目标”按钮和 `x` 急停按钮。
- 调试窗口中的 `LEFT_TARGET`、`RIGHT_TARGET` 现在只是摄像头按左右半幅输出的两个显示槽，不再决定球任务选择哪个目标。

## 5. 红球视觉识别与距离标定

### 5.1 强红种子、弱红边缘与高光修复

红球检测从单一阈值升级为带保护的连通域识别：

- 弱红门：`R >= 45`、红色优势至少 8、红色占 RGB 总量至少 380‰，用于保留暗边缘和低饱和边缘。
- 强红种子：红色优势至少 40、红色占比至少 420‰，防止弱红背景自行成为球。
- 高光修复：最多两次局部扩张，仅吸收被至少 3 个同色邻域包围的高亮低色度像素；高光像素不能独立生成目标。
- 最终继续检查面积、填充率、圆度、强色比例、平均颜色优势、置信度和画面边缘。
- 普通红球需要 3 帧稳定确认；40 cm 小目标使用面积 2‰、置信度 900 和 5 帧确认的独立远距门。

### 5.2 P0～P40 距离标定

完整数据保存在 [红球距离标定记录.md](红球距离标定记录.md)。关键中位值如下：

| 实际位置 | center_y | bbox_bottom | width/height | area |
| --- | ---: | ---: | --- | ---: |
| 球在夹子内 P0 | 837 | 932‰（原始行 55/59） | 162/200 | 25 |
| 距夹子 10 cm | 651 | 729‰（原始行 43/59） | 125/150 | 13 |
| 20 cm | 518 | 559‰（原始行 33/59） | 62/83 | 5 |
| 30 cm | 454 | 508‰（原始行约 30/59） | 75/100 | 6 |
| 40 cm | 408 | 441‰（原始行 26/59） | 50/66 | 2 |

当前入夹判据以位置为主：`center_y >= 760`、`bbox_bottom >= 850`，并要求 `height >= 130` 或 `area >= 10`。第一帧满足立即停车，最多 5 个静止画面内累计 2 次满足后才认为球已入夹。

## 6. 蓝色目标识别

蓝色矩形使用独立于红球的颜色门和连通域：

- 弱蓝：`B >= 70`、蓝色优势至少 16、蓝色占比至少 390‰。
- 普通目标要求平均蓝色优势至少 55，避免大块淡蓝背景误识别。
- 远距离侧面目标可小至 3 个相连像素，其中至少 2 个强蓝种子，平均蓝色优势至少 24，置信度至少 720，圆度至少 250‰，并使用 5 帧确认。
- 检测器仍在左右半幅各保留一个最佳蓝色连通域，避免大目标完全遮蔽另一侧只有几像素的小目标。

最终运动逻辑不再把左右半幅解释为固定的“左目标”和“右目标”。启动 `b` 后：

1. 小车始终先搜索红球；只看到蓝色不会改变找球动作。
2. 找红球期间，最早稳定确认的任意蓝色目标被记为优先目标。
3. 若两个目标同帧确认，先比较稳定帧数，再比较置信度和有效像素数，不按屏幕左右决定。
4. 目标跨越画面中心时，使用相邻画面的空间连续性保持目标选择。
5. 红球确认后，已选择的目标立即用于路线横移、推球方向和完成判定。

## 7. 红球接近、入夹与推送状态机

新增 `ball_approach.c/.h`，通过串口 `b` 或调试窗口独立运行，暂未自动拼接到巡线避障的 `FINISHED` 后。

### 7.1 总体流程

```text
找红球并记录优先蓝色目标
-> 红球候选停车确认
-> 球/目标路线横移预对齐（目标已见时）
-> 红球短脉冲对中
-> 三级减速接近
-> 静止入夹确认
-> 搜索目标（此前未见或暂时丢失时）
-> 横移微调目标方向
-> 推球
-> 严格重合确认
-> BALL_DONE
```

### 7.2 搜索与所有角度修正

为避免连续自旋越过目标，所有球任务原地转动都改为“小角度动作—停车观察”：

| 动作 | 速度 | 动作时间 | 停车观察 |
| --- | ---: | ---: | ---: |
| 找红球 | 360 | 80 ms | 200 ms |
| 对齐红球 | 300 | 80 ms | 200 ms |
| 入夹后找蓝区 | 260 | 80 ms | 200 ms |

红球搜索固定先左，左侧累计电机开启 800 ms 后切换右侧，右侧累计 1600 ms 后切回左侧；每个 80 ms 小步之间都完整停车观察。

### 7.3 横移对齐

- 红球与蓝色目标路线预对齐使用 300 指令、80 ms 横移脉冲和 200 ms 停车观察。
- 球入夹后的目标方向修正也从原地旋转改成同样的横移微调，减少夹子内红球因转动而被甩开。
- 路线误差死区为 100‰，连续 3 帧确认；预对齐最长 2.5 秒，超时后按当前最佳结果继续。

### 7.4 接近速度与静摩擦

接近速度按红球 `center_y` 分级：

- 远距离：300。
- 中距离（`center_y >= 520`）：250。
- 近距离（`center_y >= 700`）：210。
- 每次开始接近时先用 360 持续 100 ms 克服静摩擦。

曾尝试将所有接近速度降低 30%，但实车无法可靠克服静摩擦，因此已经回退到上述原始速度。

### 7.5 推球速度与终点判定

- 推球启动助力从 360/100 ms 提高到 420/180 ms。
- 推球稳态从 250 提高到 300，目标中心误差用于有限幅度的前进纠偏。
- 目标偏差超过 180‰ 时先停车，再进入横移微调。
- 完成判定取消原来的蓝框外扩 60‰：红球和蓝区都必须处于已确认状态，红球中心必须真正进入所选蓝框。
- 第一帧满足立即停车，连续 3 个静止新画面满足后才进入 `BALL_DONE`。

## 8. 异常恢复与安全约束

- 相机数据过期、红球/目标丢失、接近超时、推球超时或总流程超时会立即输出零电机。
- 球任务随后进入 `BALL_RECOVERY_WAIT`，等待 2 秒；摄像头恢复新鲜后从左侧找球重新开始，不再锁死在策略层 `BALL_FAILSAFE`。
- 底层配置错误、驱动错误和硬件故障保护仍然保留，不能由恢复等待绕过。
- `b` 只允许从 `IDLE` 启动；`x`、手动命令、硬件 RESET 和顶层故障仍可抢占球任务。
- 上电默认保持电机 EN/STBY 关闭；今日所有烧录后的被动检查都未发送运动命令。

## 11. 已知限制与后续建议

1. 固定入场的 20 cm 和约 60° 仍是时间开环估计，需要在实际赛道重新测量。
2. 80×60 保证了控制帧率，但 30～40 cm 的球和侧面蓝区只有几个像素，远距位置会有明显量化抖动。
3. 两个外观近似的蓝区同时交叉或长时间离开画面时，只靠视觉连续性无法形成永久物理身份；当前策略以最先稳定看到的目标为优先，并在连续可见时保持轨迹。
4. 推球终点现在使用零外扩、3 帧确认，仍应采集“刚进入”和“完全进入”两组实物画面确认最终停车位置。
5. 球任务目前是独立 `b` 模式，尚未自动接到巡线避障 `FINISHED` 后。
6. 下一次运动测试应先架空检查横移和旋转方向，再落地测试，并始终准备使用 `x` 或 RESET 停车。
