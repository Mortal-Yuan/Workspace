# 2026-09-01 摄像头巡线、避障与红球识别综合开发总结

## 1. 今日工作结论

今天围绕三轮全向小车完成了摄像头巡线、矩形避障、终点停车、颜色球识别、视觉抗阴影和现场
下载链路的连续开发与实车标定。最终活动固件已经写入确认过身份的 ESP32-S3，核心行为为：

```text
摄像头巡线
  -> 原始超声回波进入 20～60 mm
  -> 同周期停车并刹停 150 ms
  -> 左移 1170 ms
  -> 停稳 150 ms
  -> 前进 1191 ms
  -> 停稳 150 ms
  -> 右移最多 960 ms，并在首次见线的同周期停车
  -> 静止确认线路 5 个控制周期
  -> 使用摄像头正常巡线前进 1000 ms
  -> 锁存 FINISHED，电机输出归零
```

摄像头 T 形终点和虚拟 `1111` 不再参与终点判定。红球检测已经完成并接入遥测，但保持只读，
不会影响巡线、避障或电机输出。

## 2. 项目代码和硬件状态核对

今日首先重新核对了项目源码、测试、实验记录、硬件资料和当前引脚定义，确认：

- 主控：ESP32-S3-DevKitC-1 / ESP32-S3-WROOM-2，ESP-IDF 5.4.4；
- 底盘：三轮 Kiwi 全向结构，A=右轮、B=后轮、C=左轮；
- 已验证前进基底：`A=-speed, B=0, C=-speed`；
- 主巡线传感器已经由四路红外替换为 USB UVC 摄像头；
- 摄像头工作在 MJPEG 640×480 @ 15 FPS，JPEG 以 1/8 比例解码为约 80×60 RGB888；
- 超声波为 HC-SR04，采用非阻塞双边沿测距；
- 下载和诊断使用 CP210x UART0，而不是原生 USB Serial/JTAG；
- 所有运动命令最终只由 `app_controller` 仲裁一次并交给 `motor_driver_apply()`，避免巡线和
  避障同时写电机。

## 3. 避障姿态实验、撤销与横移修正

### 3.1 障碍前航向对齐实验

针对“小车到达障碍物时姿态不确定”的问题，曾设计并完成一版 `ALIGN_HEADING` 状态：

- 小车放在正对障碍约 20 cm 处进行视觉标定；
- 物理平行姿态对应的摄像头 `heading` 中值约为 `-383‰`；
- 对齐允许误差设为 ±80‰，要求连续 3 个不同摄像头帧满足；
- 单次旋转脉冲先后试验 50 ms、100 ms 和 30 ms；
- 旋转期间只输出原地旋转，不输出前进或横移，并保留超时和超声不确定保护。

实车测试中该状态只旋转一次便进入锁存 `FAILSAFE`，而且旋转速度和帧间控制仍不够可靠。按照
现场决定，最终源码彻底删除了 `ALIGN_HEADING` 状态、转移、配置、快照接口和对应测试，不保留
关闭状态的旁路代码。现在 `BRAKE` 结束后直接进入左移，避免该实验逻辑再次干扰避障。

### 3.2 左移偏航和距离修正

针对左移轻微逆时针偏航且幅度略大的现象，完成以下调整：

| 参数 | 修改前 | 当前值 |
| --- | ---: | ---: |
| 左移顺时针反偏航补偿 | 500‰ | 550‰ |
| 左移持续时间 | 1231 ms | 1170 ms |
| 左移稳态/起步命令 | 380/500 | 380/500 |
| 右移反偏航补偿 | 500‰ | 500‰ |

当前典型 Kiwi 电机命令为：

| 动作 | 稳态 A/B/C | 起步 A/B/C |
| --- | --- | --- |
| 左移 | `-300/-589/+300` | `-300/-775/+300` |
| 前进 | `-400/0/-400` | `-500/0/-500` |
| 右移 | `+300/+570/-300` | `+300/+750/-300` |

## 4. 避障触发距离和矩形路径优化

实车发现 100 mm 触发会让小车离障碍较远便开始横移，从而降低越过障碍物的余量。最终将原始
Echo 触发区间由 20～100 mm 收紧为 20～60 mm：

- `60 mm` 包含在近障触发范围内；
- `61 mm` 及以上继续正常巡线；
- 判定仍优先使用原始 Echo，因此不等待中值滤波接受突然出现的近障；
- 干净无回波、超量程回波和干净离群仍按空旷处理，不会误停正常巡线；
- Echo 卡高、边沿畸形等电气不确定在绕障动作中仍保留 `FAILSAFE` 保护。

触发点靠近约 40 mm 后，固定前进段没有回退到旧版 940 ms，而是保留 1191 ms，使车辆相对障碍
物多获得约 40 mm 的纵向越过余量。左移 1170 ms、右移最多 960 ms 和各段 150 ms 停稳时间保持
不变。

## 5. 回线和终点停车重新设计

### 5.1 T 形终点识别实验

根据现场终点照片，完成过一版 T 形终点分类和相机视图诊断：

- T 形连通域宽度门槛 800‰、面积门槛 200‰；
- 两个不同解码帧确认；
- 新增仅允许在 `IDLE` 使用的串口 `p` ASCII 摄像头视图；
- T 形候选在未确认时仍能作为普通连通黑线使用。

随后为了避免终点逻辑介入绕障过程，当前自动运行始终关闭该识别门禁。分类代码保留用于诊断和
主机测试，但 T 形与 `1111` 均不能触发停车。

### 5.2 最终计时终点方案

最终完成的终点流程为：

1. 右移期间首次检测到任意黑线，在同一个 20 ms 控制周期输出零；
2. 静止累计 5 个控制周期仍见线，进入 `POST_BYPASS_FORWARD`；
3. 恢复正常摄像头巡线和转向修正，持续 1000 ms；
4. 时间到达后进入锁存 `FINISHED`，暂停巡线并持续输出零。

如果右移 960 ms 内没有找到线，或者静止确认期间丢线，状态机会停止开环右移并把控制权交回
巡线丢线搜索，而不是直接锁死在 `FAILSAFE`。最后 1000 ms 内出现 `1111` 也不会提前结束。

## 6. 巡线黑色判定抗阴影优化

为减少把灰色阴影当作黑线的情况，二值化由原先的 `Otsu + contrast/8` 收紧为：

```text
black_threshold = min(Otsu + contrast/16, 120)
```

当前规则还要求画面对比度至少为 30。绝对灰度上限 120 可避免较暗但不是真正黑胶带的阴影，
仅因属于 Otsu 暗类而被接收。主机测试覆盖了：

- 白色 225 背景上的灰度 130 连通条纹必须被拒绝；
- 白色 225 背景上的灰度 90 黑线仍能识别；
- 25/225 黑白测试图的阈值由旧规则 50 收紧为 37。

ROI 保持为完整图像横向 25%～75%、纵向 60%～93%，摄像头中心安装补偿保持 `-165‰`。连通域
仍采用八邻域，历史只参与软排序，不用硬跳变阈值拒绝急弯。

## 7. 颜色球识别设计与现场标定

### 7.1 绿色球原型

今日先使用绿色球完成颜色连通域、面积、填充率、圆度、边缘排除和连续帧跟踪原型，并通过现场
放入、移除和重新放入验证了候选会随实物出现和消失。该阶段确认了同一张 80×60 RGB888 图可以
同时服务巡线和球检测，而不需要第二次 JPEG 解码。

### 7.2 切换为真实比赛红球

根据实际目标切换为红球检测，新增 `camera_ball_vision.c/.h`。当前参数为：

| 条件 | 当前值 |
| --- | ---: |
| 单像素最低 R | 45 |
| `R-max(G,B)` 单像素优势 | 8 |
| `R/(R+G+B)` | ≥380‰ |
| 连通域平均红色优势 | ≥40 |
| 最小整帧面积 | 5‰，80×60 时约 24 像素 |
| 最小包围盒填充率 | 350‰ |
| 最小短边/长边圆度 | 600‰ |
| 图像边缘留白 | 2 像素 |
| 连续帧球心容差 | 200‰ |
| 确认帧数 | 3 |

真实红球曾稳定检测在 `x=-81..-84‰、y=714..717‰`，平均 RGB 约 `160/97/90`。移除后输出恢复
为 `BALL=2/0/0/0`。针对弱红背景约 `98/74/47` 偶尔抢占候选的问题，增加连通域平均红色优势
40 的过滤；最终红球稳定于 `x=+41..+43‰、y=716..717‰`，移除后连续 12 秒无候选。

球检测遥测包括颜色、候选、确认、稳定帧、球心、尺寸、面积、填充率、圆度、置信度、平均 RGB
和最红像素探针。该功能目前只观察，不接入找球、靠近或推球动作，因此不会改变巡线周期和运动
仲裁结果。

## 8. 当前完整硬件连接

| 模块 | 信号 | ESP32-S3 引脚 | 说明 |
| --- | --- | ---: | --- |
| 启动键 | BOOT | GPIO0 | 低有效，仅启动；RESET/EN 为硬件急停/复位 |
| HC-SR04 | Trig / Echo | GPIO6 / GPIO13 | Echo 输入下拉、双边沿中断 |
| 电机公共 | STBY/EN | GPIO7 | 高有效，零命令时关闭，建议外接约 10 kΩ 下拉 |
| A 右轮 | PWM / IN1 / IN2 | GPIO9 / GPIO10 / GPIO11 | LEDC 通道 0 |
| A 编码器 | EA / EB | GPIO18 / GPIO8 | 当前仅诊断 |
| B 后轮 | PWM / IN1 / IN2 | GPIO12 / GPIO14 / GPIO15 | LEDC 通道 1 |
| B 编码器 | EA / EB | GPIO39 / GPIO40 | 当前仅诊断 |
| C 左轮 | PWM / IN1 / IN2 | GPIO16 / GPIO17 / GPIO21 | LEDC 通道 2 |
| C 编码器 | EA / EB | GPIO41 / GPIO42 | 当前仅诊断 |
| UVC 摄像头 | D- / D+ | GPIO19 / GPIO20 | 摄像头 5V，全部模块共地 |
| TFT | MOSI / CS / DC / SCLK / RST | GPIO5 / GPIO3 / GPIO38 / GPIO45 / GPIO47 | ILI9163B，SPI2 Mode 0 |
| CP210x UART0 | ESP TX / ESP RX | GPIO43 / GPIO44 | ESP TX 接转换器 RX，ESP RX 接转换器 TX，115200 |

注意事项：TFT MOSI 已从旧 GPIO20 接法改为 GPIO5，不能与摄像头 D+ 冲突；GPIO3 建议约 10 kΩ
上拉，GPIO45 建议约 10 kΩ 下拉。HC-SR04 当前现场记录为 3.3V 供电、Echo 直连；若改用 5V，
Echo 必须先分压或电平转换到 3.3V。

## 11. 当前边界和下一步

- 最新 60 mm 触发和回线后 1000 ms 巡线已经烧录，但仍需完整落地跑一次，记录是否碰撞、是否
  完全越过障碍以及最终停车位置；
- 左右横移和前进仍为开环时间控制，需在比赛地面多次测量并用中位数继续标定；
- 编码器输入在电机未运动时仍可能出现大量干扰计数，完成上拉、屏蔽、接地和滤波前不能用于
  避障距离闭环；
- 红球识别目前故意不驱动车辆。后续找球、靠近和推球应设计为独立、限速、可急停的状态机，
  并在接入电机仲裁前单独评审；
- RESET/EN 和串口 `x` 始终作为现场停车手段，首次完整测试应保持足够空间并随时可触达 RESET。
