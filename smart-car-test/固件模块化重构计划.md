日期：2026-08-26
目标平台：ESP32-S3 / ESP-IDF 5.4.4

## 1. 结论

本次重构已经按“独立计划—独立审查—主 agent 实施”的流程完成。独立审查在第三轮通过；实现不再编译原先 1530 行的 `main/main.c`，而是由单一 ESP-IDF component 下的多个静态 C 模块组成。巡线与当前临时避障行为保持兼容，电机只有一个最终写入点，控制路径不进行动态内存分配，也不进行串口阻塞输出。

当前只完成代码、测试和镜像构建，尚未把重构镜像烧录到实车。板上仍是重构前的已验证镜像，便于需要时回退和对照实车行为。

后续变更：2026-08-27 已移除本计划最初保留的巡线非零最低输出和启动/换向
增力。原因是这两个开环后处理会覆盖电机速度控制结果，增大过弯半径并降低
稳定性。下文相关条目仅作为当时重构合同和历史测试记录，不代表当前行为。
同日的中间实验曾依次恢复 8 月 25 日差速基线、同比提速、封存差速改用 A/C
同速降速控制，并把简化轮速提高 30%。这些过程保留在实验日志中。当前最终状态
再次以 8 月 25 日下午最后提交 `da7a8aa` 为版本边界，活动巡线完整恢复其前序
`10c8414` 引入的公式、状态逻辑和原始参数；后来的简化实现改为 `.disabled`
归档。随后针对实车动力不足，在不改变权重、锁向和差速结构的前提下同比提高
基础速度/修正能力，并加入只作用于绝对目标≥200驱动轮的500/150 ms起步增力；
随后把中心单探头 `0010/0100` 的内侧轮命令从 8 单独提高为 100，但仍低于增力
阈值并服从方向锁存。横移运动学和今天的矩形避障状态机始终不在巡线修改范围内。

## 3. 模块结构

```text
main/
├─ app_main.c                  极小启动入口
├─ app/
│  ├─ app_config.*             所有可调参数和配置校验
│  └─ app_controller.*         顶层模式、命令意图、唯一运动仲裁点
├─ control/
│  ├─ line_follow.*            纯巡线控制器
│  └─ obstacle_supervisor.*    当前停车等待型避障监督器
├─ core/
│  ├─ app_events.h             命令、模式和故障类型
│  ├─ config_types.h           跨层只读配置类型
│  ├─ diagnostic_types.h       诊断事件和快照类型
│  ├─ motion_types.h           三轮运动命令
│  └─ sensor_types.h           红外、超声事件和质量类型
├─ drivers/
│  ├─ motor_driver.*           缓存写入、安全换向、EN/STBY、故障锁存
│  ├─ ultrasonic.*             非阻塞触发、边沿捕获、滤波和事务保护
│  ├─ line_sensor.*            主动低电平红外输入归一化
│  ├─ encoder.*                三路编码器 ISR 与一致快照
│  └─ start_button.*           BOOT 防抖、释放重装和上电保护
├─ diagnostics/
│  └─ diagnostics.*            低优先级异步格式化和双串口发送
└─ platform/
   ├─ board_pins.h             唯一引脚/LEDC 通道映射
   ├─ motor_hal*               ESP-IDF 电机硬件适配层
   └─ platform_init.*          GPIO ISR service 初始化
```

依赖方向固定为：`app -> control/drivers/diagnostics -> core/platform`。控制算法不直接调用 GPIO、LEDC、UART，也不包含板级引脚。新增策略必须输出 `motion_policy_t`/`motor_command_t`，不能绕过顶层仲裁直接写电机。

## 4. 每个控制周期的数据流

```text
GPIO/ISR -> typed sensor event/snapshot
        -> obstacle supervisor + line controller
        -> top-level motion arbitration
        -> motor_driver_apply()（唯一最终写入）
        -> cached HAL writes / EN-STBY

control task -> static diagnostic queues -> low-priority diagnostic task
```

控制任务采用 20 ms 绝对周期。每次唤醒最多执行一个控制步；超时时重新对齐下一周期，不进行补跑忙循环。诊断格式化、USB Serial/JTAG 和 UART0 发送均移到低优先级任务，发送采用有限分片和零等待调用。遥测队列长度为 1，允许新快照覆盖旧快照；故障和关键状态转换使用独立队列。

## 5. 安全与行为合同

### 电机

- 上电首先配置 EN/STBY 为关闭，方向和 PWM 完成配置后才允许使能。
- 全零命令先关闭 EN/STBY，再清 PWM。
- 方向反转严格执行“该轮 PWM=0 -> 改方向 -> 写新 PWM”。
- 相同命令不重复访问 GPIO/LEDC，降低控制周期的硬件写入量。
- 任一 HAL 写入失败会立即尝试关闭 EN/STBY并锁存故障；只有明确的安全重新初始化才能解除可恢复故障。

### BOOT 与 RESET

- BOOT：按下稳定 50 ms；稳定释放后再等待 80 ms 才重新装填；上电保护 500 ms。
- 保护期内形成的有效短按会排队；上电时已经按住则必须先释放再按。
- BOOT 在自动模式中仍是“只启动”，不会切换成停止。
- RESET/EN 是硬件复位输入，不是普通 GPIO。复位后启动路径首先关闭电机；仍建议在电机驱动 EN/STBY 上保留约 10 kΩ 外部下拉。

### 巡线

- 当前合同为：直线 360、普通弯 250/上限 400、单侧边缘 190/上限 320、搜索
  320、`Kp=100`、最大修正 250、默认速度上限 400。
- 误差为 `(-6L-2LC+2RC+6R)/有效探头数`，A/C 使用相反的比例修正；普通弯和
  单侧边缘按最大绝对命令同比例缩放。
- 保留三周期方向确认、反向未确认时至少 4 的方向保持误差、全白时按锁存方向
  搜索，以及 A=右轮、B=后轮、C=左轮的实测映射。
- 不使用弯道非零最低命令。原始绝对目标达到 200 的驱动轮在进入该角色或换向
  时使用 500/150 ms；`0010/0100` 的内侧轮固定为 100，其他 43/44 低需求命令
  不增力。

### 当前矩形避障

```text
SENSOR_CHECK --连续三次明确无障碍--> CLEAR
CLEAR --首个 20..50 mm 真实回波--> BRAKE
BRAKE -> LEFT_EDGE -> LEFT_CLEARANCE -> SETTLE_FORWARD
-> FORWARD_BYPASS -> SETTLE_RIGHT -> RIGHT_LINE
-> LINE_CONFIRM -> CLEAR（恢复巡线）
```

自动绕障当前参数：阈值 50 mm、启动清空确认 3 次、板边清空确认 3 次、
回线确认 5 周期、制动 150 ms、横移稳态/启动 380/500、运动启动增力 150 ms、
横移越边 800 ms、前进稳态/启动 400/500、前进 2500 ms，找边和找线超时均为
5000 ms。800/2500 ms 仍是待场地标定值。近距、无效/异常回波、Echo 高或并发
异常都按当前 fail-safe 规则阻断运动。

超声波每次触发都有独立 session generation 和 trigger token。ISR 记录的完整脉冲在临界区内优先于任务超时结算；迟到边沿不能写入下一次事务，完整脉冲也不会被下一次触发清除。

## 6. 面向未来避障的扩展方法

未来加入绕木板、IMU 航向或更复杂行为时，不修改电机驱动和巡线算法：

1. 在 `drivers/` 增加新传感器驱动，并在 `core/` 定义不可变事件/快照。
2. 将 `obstacle_supervisor` 扩展或替换为分层状态机；每步只返回 `BLOCK`、`LINE_FOLLOW` 或 `OVERRIDE` 及一个三轮命令。
3. 将所有阈值、时间和速度放入 `app_config`，禁止在状态分支中散布魔法数字。
4. 由 `app_controller` 保持唯一的模式切换和运动仲裁，最终仍只调用一次 `motor_driver_apply()`。
5. 为新状态机先增加主机侧事件序列测试，再做限制时间、低速、轮子悬空的实车分段测试。

该边界允许后续新增板边跟随、IMU 航向恢复、路径规划或任务行为，而不复制 GPIO/PWM、按钮、诊断和故障处理代码。

## 8. 首次实车验证顺序

1. 架空车轮烧录，确认启动后模式为 `IDLE`、命令为 `0,0,0`、EN/STBY 关闭。
2. 验证 RESET 立即复位并保持停车；验证 BOOT 单次启动且运行中重复按不切换状态。
3. 分别执行受限 `r` 和 `t` 测试，确认三轮方向没有因重构改变。
4. 架空或低风险场地验证巡线输出与重构前一致。
5. 放置 50 mm 内障碍，确认首帧近距事件即停车；保持障碍时计数为 `0/3`。
6. 移开障碍，确认恰好三次明确无障碍后恢复巡线。

完成这些步骤前，不启用未来自动绕板状态机。
