# 2026-09-09 小车机械臂通讯与低位抓取开发总结

## 1. 本日目标与结果

今天完成了小车 ESP32-S3 与机械臂 KPZ-ESP32 之间的独立 UART 通讯基础设施、实机双向连通验证，以及机械臂低位抓取终点的手动示教记录。

当前成果边界如下：

- 两块控制板已经能通过带序号的 `PING/PONG` 报文双向通讯。
- 小车端已具备独立的机械臂通讯驱动、接收事件解析和安全诊断命令。
- 机械臂端已具备不会驱动舵机的 `PING` 响应模块。
- 已记录用户手动摆出的低位抓取姿态，并生成“张开到位”和“闭合夹爪”命令。
- 尚未把低位抓取动作接入小车自动任务，也未执行新生成的低位姿态命令。

## 2. 硬件与接线确认

本日最终采用专用 3.3 V TTL UART，参数为 `115200 8N1`：

| 小车 ESP32-S3 | 方向 | 机械臂 KPZ-ESP32 |
| --- | --- | --- |
| GPIO1 / UART1 TX | → | GPIO21 / SD6 / UART1 RX |
| GPIO2 / UART1 RX | ← | GPIO22 / SA6 / UART1 TX |
| GND | — | GND |

注意事项：

- TX 与 RX 交叉连接，两块板必须共地。
- 两块控制板独立供电，不通过通讯线互接 `5V` 或 `3V3`。
- 机械臂板面的 K1 是 GPIO36 按键，不属于 UART 通讯线。
- 机械臂“用户接口”的 GPIO16/17 与原有舵机总线 UART2 路径存在共享关系，本方案不占用该接口。

实机已完成 `CAR,PING,0001` → `ARM,PONG,0001` 的双向验证。

## 3. 小车端代码修改

### 3.1 新增机械臂 UART 驱动

新增：

- `main/drivers/arm_link.c`
- `main/drivers/arm_link.h`

实现内容：

- 使用 ESP32-S3 的 UART1，波特率 `115200`。
- 发送带 4 位序号的 `CAR,PING,xxxx` 报文。
- 非阻塞接收并解析 `PONG`、`ACK`、`BUSY`、`DONE`、`ERROR` 和未知报文。
- 接收行最大长度限制为 64 字节，溢出时丢弃当前不完整行，避免越界。
- 序号从 1 开始递增，回绕后跳过 0。

### 3.2 控制器接入

修改 `main/app/app_controller.c` 和 `main/app/app_controller.h`：

- 在控制器状态中加入 `arm_link` 和 `arm_link_ready`。
- 初始化机械臂 UART；初始化失败时设置 `DEGRADED_ARM_LINK`，不冒充通讯正常。
- 增加串口命令 `i`，用于发送一次安全的机械臂 `PING`。
- `i` 只允许在小车处于 `IDLE` 或 `FAULT` 且没有其他动作意图时发送，诊断期间轮子保持零输出。
- 控制循环轮询机械臂反馈，并通过诊断事件报告报文类型和序号。
- 摄像头初始化失败时保留零输出控制循环和诊断链路，但故障位仍会阻止小车运动，从而可以在摄像头故障状态下独立检查机械臂通讯。

### 3.3 引脚与构建系统

修改 `main/platform/board_pins.h`：

- `BOARD_PIN_ARM_LINK_TX = GPIO_NUM_1`
- `BOARD_PIN_ARM_LINK_RX = GPIO_NUM_2`

修改 `main/CMakeLists.txt`，将 `drivers/arm_link.c` 加入 ESP-IDF 组件构建。

## 4. 机械臂端代码

### 4.1 小车通讯响应模块

新增 `arm-readback/2026-09-08/factory/z_car_link.py`：

- 在机械臂 GPIO22/TX、GPIO21/RX 上初始化 UART1。
- 采用缓冲、换行分帧方式接收报文。
- 只对格式正确的 `CAR,PING,xxxx` 回复 `ARM,PONG,xxxx`。
- 模块本身不调用舵机接口，不会产生机械臂动作。

当前它仍是独立模块，尚未自动合并进机械臂原厂 `z_main.py` 的永久启动循环。

### 4.2 自定义低位抓取命令模块

新增 `arm-readback/2026-09-08/factory/z_custom_grab.py`。该模块只保存姿态并生成字符串，导入模块不会发送命令或驱动舵机。

用户在舵机卸力状态下手动摆出的六路读数为：

| 舵机 ID | 000 | 001 | 002 | 003 | 004 | 005（夹爪） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 手动示教值 | 1496 | 788 | 1816 | 1265 | 1496 | 1235 |

原样回到示教位置的命令：

```text
{#000P1496T3000!#001P0788T3000!#002P1816T3000!#003P1265T3000!#004P1496T3000!#005P1235T3000!}
```

为了使夹爪初始状态可重复，正式的低位张开到位命令使用原厂张开值 `1200`：

```text
{#000P1496T3000!#001P0788T3000!#002P1816T3000!#003P1265T3000!#004P1496T3000!#005P1200T3000!}
```

闭合夹爪命令：

```text
#005P1700T1000!
```

详细记录见 `arm-readback/2026-09-08/自定义低位抓取动作.md`。

## 5. 机械臂动作试验与安全状态

- 已识别机械臂控制器为 ESP32-D0WD-V3 rev3.1、4 MB Flash，MicroPython v1.18。
- 六个舵机 ID `000`～`005` 均能响应查询。
- 原厂前抓动作组曾执行一次，之后按用户要求对六个舵机发送卸力命令。
- 从竖直状态逐步降低抓取点时，邻近低位曾出现持续抖动，表明该姿态附近的肩关节负载较大。
- 随后保持卸力，由用户手动摆出并读取了上述最终姿态。
- 本日没有执行新生成的低位抓取命令，没有恢复舵机扭力，也没有修改原厂 `action.txt`。
- 机械臂原厂主程序仍保持在 MicroPython REPL 中断状态；不要在没有支撑机械臂和清空工作区时复位或恢复扭力。
