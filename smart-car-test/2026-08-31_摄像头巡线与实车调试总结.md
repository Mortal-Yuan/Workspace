# 2026-08-31 摄像头巡线与实车调试总结

## 1. 文档范围

本文汇总 2026-08-31 完成的摄像头画面裁剪、二维连通区域巡线、几何标定、急弯处理、
丢线搜索、近端盲区轨迹记忆、超声空旷判断、速度调整、现场诊断以及最终的软历史候选
选择。文中会区分当天尝试后撤回的中间方案和当前代码实际生效的最终方案。

当天工作的核心目标是让车辆在以下实际限制下仍能完成巡线：

- 摄像头已经安装到最低，但最近只能看到车前约 10 cm 以外的黑线；
- 急弯会在很短的直线后快速转向，不能用严格的直线形状或历史跳变条件拒绝黑线；
- 中央视野可能同时出现赛道黑线和环境深色区域；
- 丢线、低对比度和没有候选区域属于可恢复的巡线异常，不应让车辆永久停车；
- 实际赛道大部分时间没有障碍，超声波无回波或超时通常代表空旷，而不是故障。

## 2. 当前硬件连接与数据通路

### 2.1 摄像头与主控

当前使用 USB UVC 摄像头，已确认设备标识为 `VID=0x349c`、`PID=0x3307`，连接如下：

| 摄像头信号 | ESP32-S3 |
| --- | --- |
| 5V | 5V |
| GND | GND |
| D- | GPIO19 |
| D+ | GPIO20 |

摄像头已经物理正装，固件使用原生画面方向，不再软件旋转 180°。USB Host 接收
MJPEG 640×480 @ 15 fps，JPEG 解码时直接缩小到 RGB888 80×60，以降低运算量和内存
占用。

### 2.2 相关接口占用

- CP210x UART0 下载和诊断：`TX=GPIO43`、`RX=GPIO44`，115200 bit/s；
- HC-SR04：`Trig=GPIO6`、`Echo=GPIO13`；
- TFT：`MOSI=GPIO5`、`SCK=GPIO45`、`CS=GPIO3`、`D/C=GPIO38`、`RST=GPIO47`；
- GPIO19/20 已固定用于摄像头 USB D-/D+，显示屏旧的 `SDI--GPIO20` 接线必须移除；
- 四路红外巡线模块已经停用，其 VCC/GND/OUT 线可以全部拆除。

## 3. 摄像头画面范围与二值化

### 3.1 下半幅硬裁剪

解码仍得到完整的 80×60 图像，但视觉分析入口只接收下半幅。最终有效 ROI 为原始画面的：

- 横向：`x=25%～75%`；
- 纵向：`y=60%～93%`。

上半幅和中央横向窗口之外的像素不会参与直方图、阈值、连通区域或转向计算。当天曾短暂
取消横向 50% 限制，使用全宽画面捕获极端边缘急弯；实测发现环境深色干扰风险明显增加，
因此最终恢复中央 `25%～75%` 横向窗口。下半幅硬裁剪始终保留。

### 3.2 自适应黑色阈值

中央 ROI 使用亮度直方图、Otsu 阈值和对比度修正生成二值图。当前最小对比度为 30；
低对比度时结果有效但不产生黑线候选，由后续巡线异常流程进入找线。二值化用于区分黑白，
不再把面积、宽度、纵向跨度等几何量作为普通线路的硬准入条件。

## 4. 二维连通区域与候选选择

### 4.1 八邻域二维连通

旧的一维“连续黑列”方案已经替换为八邻域二维连通区域搜索。水平、垂直、斜向和弧形
像素均可连接，因此短直线后立刻转弯的黑线不会仅因形状弯曲而被断开。

每个非空八邻域连通区域都具有普通线路候选资格。当前没有以下硬门槛：

- 最小连通面积；
- 必须接触 ROI 底部；
- 最小纵向跨度；
- 普通线路最大宽度；
- 首次必须靠近中心；
- 相对历史位置或方向的最大跳变。

这项简化可以最大限度避免急弯被复杂规则误拒绝，但也意味着短黑块、宽黑块、单像素和
环境深色物都可能成为候选。

### 4.2 最终软历史选择

没有可靠历史时，多个候选中继续选择像素面积最大的连通区域。连续识别 3 帧普通线路后，
保存上一条可靠线路的近端位置和转向方向，后续多个候选使用以下软评分：

```text
score = area / (250 + abs(near - previous_near)
                      + abs(steer - previous_steer))
```

得分越高越优先。该设计具有以下边界：

- 面积仍然提供有效证据，不会无条件选择靠近历史的小噪点；
- 位置和转向越符合上一条轨迹，候选越容易胜过更大的环境深色区域；
- 历史偏差只会平滑降低分数，不存在严格跳变拒绝；
- 画面只有一个连通区域时，即使它位于历史轨迹另一侧，也仍会正常接收；
- 宽终点候选不会覆盖普通线路历史，包括启动阶段终点尚未解锁时。

这一修改针对现场右后急弯中“大面积左侧深色区域压过真实右侧线路，车辆错误左转”的
现象，同时保留急弯发生大幅位置变化时的可恢复性。

### 4.3 视觉工作区稳定性

二维连通搜索需要 mask、BFS 队列、直方图和逐行统计量。第一版把这些数组放在 8192 字节
解码任务栈上，板上出现过 `InstrFetchProhibited/LoadProhibited`。最终在摄像头初始化时
从 PSRAM 一次性分配 `camera_line_vision_workspace_t`，每帧复用，不在解码任务栈或每帧
动态分配，从而消除栈破坏问题。

## 5. 10 cm 盲区下的线路几何与转向

### 5.1 固定预瞄

软件无法恢复镜头看不到的轮下像素，因此把可见黑线当作固定预瞄。对所选连通区域计算：

- `near`：连通区域自身下三分之一的加权中心；
- `far`：连通区域自身上三分之一的加权中心；
- `heading = far - near`；
- 普通转向：`steer = near + 0.5 × heading`。

中心使用亚像素加权计算，避免 80 像素宽分析图像中偶数宽黑线产生固定的半像素偏差。
2026-08-31 用车体几何中心重新标定后，安装补偿由 `+37` 改为 `-165`。静止居中实测
稳定为 `pos=-41～-39`、`steer=-54～-53`，位于直行区内部。

### 5.2 急回头弯的近远端抵消

现场右后急弯曾出现 `near≈+250`、`far≈-160`、`heading≈-410`。普通公式得到的
`steer≈+45` 接近直行，使车辆在静摩擦下表现为卡住。当前增加急弯几何规则：

```text
near 与 far 分处中心两侧
且 abs(near) >= 160
且 abs(heading) >= 300
    => heading 增益由 0.5 降为 0.1
```

同一组现场几何由 `steer≈+45` 修正为 `steer≈+209`，优先相信靠近车辆的连通区域部分，
避免远端方向把近端转向抵消。该规则只改变转向计算，不拒绝候选连通区域。

### 5.3 连续转向控制

视觉 `steer` 直接参与 A/C 两侧驱动轮差速，不再只依赖四格虚拟传感器的离散误差。
`steer=±600` 时达到当前最大 `±300` 修正，之后饱和。虚拟 `L/LC/RC/R` 仍保留给图样
状态、方向确认、绕障回线和诊断使用。

## 6. 正常巡线速度与短时轨迹记忆

### 6.1 当前最终速度

当天经过多轮 10% 和 20% 调整后，当前有效参数为：

| 项目 | 当前值 |
| --- | ---: |
| 直线基础速度 | 348 |
| 普通弯基础速度 | 276 |
| 普通弯输出上限 | 384 |
| 单侧边缘基础速度 | 233 |
| 单侧边缘输出上限 | 336 |
| 比例增益 `Kp` | 120 |
| 最大差速修正 | 300 |
| 原地找线稳态速度 | 211 |

最终一轮只把直行和正常转向整体提高 20%，并同步提高差速增益与上限；原地找线速度和
时序没有跟随该 20% 修改。

### 6.2 入弯轨迹记忆

新摄像头转向绝对值达到 180 permille、且已经存在可靠巡线命令时，控制器先沿上一条可靠
轨迹保持 180 ms，再应用新的转向。转向回落到 80 以下才重新解锁，避免每个摄像头帧都
重复启动延迟。该记忆用于跨越约 10 cm 近端盲区，使实际轨迹更贴合已经验证过的入弯路径。

### 6.3 丢线后的短时运动记忆

巡线过程中刚丢线且存在可靠运动历史时：

1. 前 120 ms 继续执行最后一次未增力的可靠巡线命令；
2. 接下来 30 ms 输出零；
3. 丢线满 150 ms 后开始原地旋转找线。

开机、无历史启动、搜索重捕获候选再次消失等没有可靠运动历史的情况，完整 150 ms 都输出
零，不会盲目前进。

## 7. 丢线与巡线异常恢复

### 7.1 哪些情况进入找线

以下情况统一视为可恢复的巡线异常，而不是永久停车条件：

- `CAM=0000`；
- 对比度不足；
- 没有连通区域；
- 普通行驶中黑线离开 ROI；
- 绕障右移到时间上限仍未见线；
- 绕障回线候选在确认阶段再次消失。

BOOT 或串口 `f` 只要求摄像头已有新鲜解码结果，不要求启动瞬间已经看到黑线。无黑线启动
会在超声确认前方安全后进入同一找线流程。

### 7.2 扩展式双向原地搜索

搜索冻结最后可靠线路方向；没有离散方向锁时使用绝对值至少 100 permille 的最后摄像头
转向符号，再无历史才默认向左。搜索各段依次为：

```text
历史方向 1.2 s
反方向   2.4 s
历史方向 3.6 s
反方向   4.8 s
历史方向 6.0 s
反方向   7.2 s
之后每段 7.2 s 持续交替
```

这样在原始朝向两侧分别达到约 1.2、2.4、3.6 秒等效旋转距离。当天早期曾使用
`1.2 s -> 2.4 s -> 1.2 s -> 2.4 s`，会导致后一轮短段只能回到中心并产生单方向漂移；
该运算已经修正。搜索没有总超时，不会因为普通丢线进入“搜索停止”状态。

找线稳态速度为 211，超过 200 的驱动增力门限，因此搜索开始和每次换向先输出 500、
持续 150 ms，再回落到 211，以克服带载静摩擦。当天曾试验 240、120、156、192，最终
采用 211。

### 7.3 三个真实摄像头帧重捕获

旋转中出现候选连通黑线时，同一控制周期立即停止旋转并进入静止确认。只有连续 3 个不同
`decoded_frames` 帧序号均看到线路，才恢复前进；20 ms 控制任务重复读取同一张 15 fps
图像不会被误计为三帧。确认期间再次丢线会回到持续搜索。

## 8. 超声空旷判断与绕障衔接

### 8.1 无回波代表正常空旷

实际赛道大部分时间无障碍，HC-SR04 的干净低 Echo 超时、无回波和完整超量程脉冲均作为
“无障碍”观测。启动或等待障碍消失时，连续 3 个有效远距回波或干净无回波的任意组合
即可进入 `CLEAR`。Echo 持续高、边沿畸形和明确电气不确定仍不能授权启动。

正常巡线已经进入 `CLEAR` 后，只有原始真实 Echo 落在 20～100 mm 才能中断巡线并开始
避障；其他无回波、远距、干净跳变和诊断异常不会让正常巡线停车。

### 8.2 绕障回线异常不再锁死停车

固定时间绕障仍为左移、前进、右移回线结构。右移到 960 ms 上限仍未看到黑线，或者已经
看到候选但确认阶段再次丢失时，立即停止开环横移、退出绕障覆盖并交还给持续找线流程，
不再进入 `FAILSAFE` 永久零输出。

绕障完成前，`1111` 仍作为普通线路图样参与巡线；完成一次绕障后，`1111` 才进入独立的
`FINISHED` 锁存停车状态。本次软历史选择没有修改该行为。

## 9. 诊断信息增强

实时状态输出新增并保留以下摄像头几何量：

- `pos`：所选连通区域近端中心；
- `far`：远端中心；
- `head`：`far-pos`；
- `steer`：最终连续转向量；
- `width`：逐行最大局部宽度；
- `comp=数量/高度/面积`；
- `black/thr/contrast`；
- `cam_drop/cam_err` 和解码帧序号。

巡线日志同时输出原始离散误差、方向确认后的控制误差、基础速度和最终 A/B/C 命令。诊断
消息缓冲由 384 字节扩展为 512 字节，避免新增字段截断。

## 12. 当前风险与下一步实车验证

1. 软历史需要先连续建立 3 帧普通线路。刚启动且没有历史时仍选择最大连通区域，如果起点
   同时存在更大的环境深色区域，仍可能先选错；应让车辆起步位置尽量只包含真实黑线。
2. 软评分没有硬拒绝，符合“急弯不被历史卡死”的要求，但面积与历史误差的权重仍需用真实
   右后急弯复测；若仍选错，只调整软评分权重，不恢复严格跳变门槛。
3. 摄像头约 10 cm 近端盲区是机械视场限制。180/120 ms 记忆是基于当前速度的经验补偿，
   速度、轮胎摩擦或相机安装变化后应重新标定。
4. 找线会持续旋转直到看见线或人工 RESET/串口 `x`，测试时必须预留空间并能立即急停。
5. 一轮无命令检查曾发现 C 路编码器在零电机命令下增长；若车轮实际静止，应检查编码器
   信号线、共地、上拉和电机/摄像头电气噪声，不能把该计数直接当作真实里程。
6. 重新连接 CP210x 后，应先烧录当前 `0x59150` 镜像并完成无命令启动检查，再在架空车轮
   条件下验证右后急弯候选是否由左侧环境区域切换为真实右侧线路，最后进行低速落地测试。
