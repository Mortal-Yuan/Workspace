# 2026-09-04 巡线、避障与双球任务优化总结

## 1. 今日目标与最终结果

今天在现有三轮全向小车基础上完成了三条主线工作：继续提高摄像头巡线和定时避障的落地可靠性；把原有红球任务扩展为“红球进左侧蓝区、绿球进右侧蓝区”的完整双球任务；将巡线避障与双球任务串联为一次可连续执行的比赛流程。

最终已写入小车的流程为：

```text
启动巡线避障
-> 摄像头巡线
-> 110 mm 内检测到障碍物
-> 固定分段绕障
-> 最后直行并停止 3 s
-> 红球送入左侧蓝区
-> 后退约 16 cm
-> 顺时针右转约 60°
-> 绿球送入右侧蓝区
-> MISSION_DONE，电机输出归零
```

双球落地测试已经完整跑通一次。日志中依次出现红球完成、绿球阶段、`BALL_PUSH`、`BALL_DONE` 和 `MISSION_DONE`，任务完成后监控程序自动发送停止指令。

## 2. 摄像头巡线优化

### 2.1 ROI 上移 8 个像素

巡线 ROI 在 80×60 解码图上整体上移 8 行，同时保持原有宽度和 19 行高度：

| 项目 | 调整前 | 当前值 |
| --- | ---: | ---: |
| 横向范围 | 25%～75% | 25%～75% |
| 纵向像素范围 | `y=36..54` | `y=28..46` |
| 纵向比例 | 60%～93% | 46.7%～79.7% |

由于新 ROI 顶部越过原来的“下半幅”边界，巡线视觉入口改为接收完整 80×60 图像，再在内部裁剪 ROI。红球、绿球和蓝区仍分析完整画面。

### 2.2 落地转向与防卡滞

保持巡线基础速度不变，只提高高需求转向时的有效轮速，解决落地负载下偶发卡住：

| 参数 | 当前值 |
| --- | ---: |
| 直行基础速度 | 348 |
| 普通弯道基础速度 | 276 |
| 普通弯道最大输出 | 420 |
| 单侧边缘基础速度 | 233 |
| 单侧边缘最大输出 | 400 |
| 丢线搜索速度 | 211 |
| 比例增益 `kp` | 120 |

驱动辅助仍只作用于实际承担驱动任务且需要克服静摩擦的车轮，不抬高低需求内侧轮。短时丢线继续保留最近可靠轨迹，随后进入逐段扩展的左右搜索。

## 3. 避障算法优化

### 3.1 当前状态机

```text
SENSOR_CHECK -> CLEAR -> BRAKE
-> LEFT_STRAFE
-> SETTLE_LEFT_TRIM -> LEFT_HEADING_TRIM
-> SETTLE_FORWARD -> FORWARD_TIMED
-> SETTLE_RIGHT -> RIGHT_RAMP
-> FINAL_FORWARD_525MS
-> FINISHED，停车 3 s
```

进入 `BRAKE` 后采用固定分段路径，巡线画面不再提前截断横移或中段前进。新障碍或底层安全异常仍可进入故障保护。

### 3.2 最终参数

| 阶段 | 当前参数 | 目的 |
| --- | --- | --- |
| 障碍触发 | 原始 Echo `20～110 mm` | 相比 80 mm 提前 3 cm 开始避障 |
| 制动 | 150 ms | 先停止巡线输出 |
| 左移 | 1468 ms，稳态 380，前 150 ms 为 500 | 绕到障碍物左侧 |
| 左移后停顿 | 150 ms | 消除轮胎滑移 |
| 车头左调 | 逆时针 460，60 ms | 抵消左移末尾车头向右偏 |
| 再次停顿 | 150 ms | 再进入直行 |
| 横移间前进 | 1243 ms，稳态 400，前 150 ms 为 500 | 在 1184 ms 基础上增加 5% |
| 右移 | 总计 625 ms | 在 1042 ms 基础上减少 40% |
| 右移渐变 | 300→380，400 ms | 降低启动打滑和突发偏航 |
| 右移偏航补偿 | `-60→0`，400 ms | 抑制启动时顺时针偏转 |
| 最后直行 | 525 ms | 完成回线方向的固定前进 |
| 任务交接 | 停车 3000 ms | 再自动进入双球任务 |

今天曾尝试在“刚识别到障碍物”时加入车头左调，但现场效果不明显，最终取消。只保留左移完成后的逆时针微调，并将其增强为 460/60 ms。

## 4. 绿色球识别与蓝区视觉

### 4.1 用绿球替代黄球

黄球与现场亮色背景容易混淆，因此改用绿球作为第二目标。绿色检测与红球、蓝区使用独立候选和稳定状态，主要颜色门限为：

- `G >= 55`
- `G-R >= 18`
- `B-G <= 20`
- 强绿色种子 `G >= 75`
- 远距离候选最少 4 个像素，其中至少 2 个强绿色像素
- 绿色球连续 3 帧确认

现场完成了“绿球可见、移位、移除”多轮标定，能够区分真实绿球与背景，并接入右侧目标任务。

### 4.2 放宽远距离蓝区识别

为适应靠近球时蓝色目标区域变小、部分离开画面的情况，蓝区使用独立于红/绿球的确认帧数和远距离门限：

| 参数 | 当前值 |
| --- | ---: |
| 最少像素 | 2 |
| 最少强蓝像素 | 1 |
| 平均蓝色优势 | 24 |
| 最低置信度 | 720‰ |
| 最低圆整度 | 250‰ |
| 连续确认帧数 | 3 |
| 目标跟踪跳变容差 | 500‰ |

该方案比早期 5 帧确认更容易维持远端蓝区，但仍要求跨帧稳定跟踪，避免单帧蓝色噪声直接成为目标。

## 5. 找球、对齐与固定踢球策略

### 5.1 球优先的接近逻辑

现场验证表明，若强制先找到并旋转对准蓝区再靠近球，小车容易长时间调整，且蓝区会在靠近过程中丢失。因此最终恢复“球优先”策略：

1. 已确认球但暂时看不到蓝区时，继续对中和接近球。
2. 接近过程中蓝区出现时，可以进行球—目标路线横移校正。
3. 路线校正期间目标暂时丢失时，退回球对中，不永久卡在目标搜索。
4. 接触球后重新搜索并对齐指定蓝区，再执行最终踢球。

接近动作增加了落地启动增力：每次由停止转为接近时先用 450 的基础增力持续 300 ms，并保证实际驱动轮不低于 400；随后恢复远/中/近距离 300/250/300 的速度分级。

### 5.2 固定踢球替代“夹持/入球判定”

小车前端只能碰球，无法稳定夹住球；球往往在第一次接触后立即滚动，因此“持续推球至少 600 ms”或持续观察球与蓝区重合会频繁失败。最终改为：

```text
确认球接触
-> 重新找到目标蓝区
-> 目标误差不超过 100‰，连续 2 帧
-> 以 500 输出直踢 500 ms
-> 直接判定当前颜色完成
```

该策略取消踢球后的复杂入球视觉判断，不再因为球滚出画面而停在当前颜色阶段。最终对齐门限从一度过宽的设置收紧到 100‰，降低踢偏概率。

## 6. 双球任务与主流程拼接

新增 `ball_mission.c/.h` 管理两种颜色的顺序和中间开环动作：

```text
RED_TO_LEFT
-> 红球固定踢入左蓝区
-> TRANSITION_SETTLE 500 ms
-> RED_EXIT_REVERSE 860 ms
-> RED_EXIT_REVERSE_SETTLE 150 ms
-> GREEN_ENTRY_TURN_RIGHT 420/200 ms
-> GREEN_ENTRY_TURN_SETTLE 300 ms
-> GREEN_TO_RIGHT
-> 绿球固定踢入右蓝区
-> MISSION_DONE
```

红球完成后的倒车使用 `A/B/C=+speed/0/+speed`，前 150 ms 为 500，之后为 400；时间由 430 ms 增加到 860 ms，开环估算距离约由 8 cm 增至 16 cm。随后保持原有约 60° 顺时针右转，再开始寻找绿球。

串口 `n` 可单独启动双球任务，用于落地调试。完整巡线入口 `f`/BOOT 在避障 `FINISHED` 后停车 3 秒，再自动启动同一双球任务；串口 `x` 和硬件 RESET 始终可以抢占停止。

## 9. 已知限制与下一步建议

1. 左移、前进、右移、红球后退和约 60° 转向仍是时间开环估算，应在最终赛道表面测量实际距离。
2. 编码器在 `cmd=0,0,0` 时仍会快速跳变，确认属于未滤波输入的电气噪声；修复硬件滤波/上拉前不能用于闭环里程控制。
3. 蓝区只有 2～4 个像素时仍可能受量化和遮挡影响，应保留实时窗口观察候选、确认和稳定帧数。
4. 右移已缩短至 625 ms，其中 400 ms 仍处于渐加速阶段；需实测确认既能回到目标路线，又不会因距离过短停在障碍物侧面。
5. 11 cm 触发距离是原始 Echo 的即时安全门，需确认赛场障碍物表面不会产生大量斜射丢波。
