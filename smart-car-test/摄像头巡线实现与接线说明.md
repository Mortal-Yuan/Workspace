# 摄像头巡线实现与接线说明

## 当前状态

主固件已经用 USB UVC 摄像头替代四路红外模块完成第一版巡线输入，现有电机
控制、BOOT 启停、超声波避障、绕障后找线、宽终点线停车和 RESET 急停逻辑
继续保留。

板上实测结果：

- 摄像头协商格式：MJPEG 640×480 @ 15 fps；
- ESP32-S3 解码识别尺寸：80×60；
- 持续解码速度：约 14 fps；
- 97 秒启动检查共处理 1354 帧；期间自动跳过 1 个损坏 JPEG 帧并立即恢复，
  无任务看门狗错误；
- 无命令启动期间电机命令始终为 `0,0,0`。

这只是安全的第一版参数。正式比赛前仍必须在实际赛道上标定摄像头高度、
俯角、ROI、阈值和行驶速度。

## 接线

### 摄像头

| 摄像头信号 | ESP32-S3 |
| --- | --- |
| 5V | 5V |
| GND | GND |
| D- | GPIO19 |
| D+ | GPIO20 |

按模块丝印识别信号，不要只按线色判断 D+、D-。摄像头使用 ESP32-S3 的 USB
Host，GPIO19/20 不再用于其他外设。

### 红外模块

红外模块的 `VCC/GND/OUT1/OUT2/OUT3/OUT4` 可以全部拆除。GPIO1、GPIO2、
GPIO4 释放；原 OUT4 使用的 GPIO5 改作显示屏 MOSI。

### 显示屏

| 显示屏信号 | ESP32-S3 |
| --- | --- |
| SDI / MOSI | GPIO5 |
| SCK | GPIO45 |
| CS | GPIO3 |
| D/C | GPIO38 |
| RST | GPIO47 |
| VCC | 3V3 |
| GND | GND |

必须把旧的 `SDI--GPIO20` 线移到 GPIO5，不能同时把显示屏和摄像头 D+ 接在
GPIO20。GPIO45 建议外接约 10 kΩ 下拉，GPIO3 建议外接约 10 kΩ 上拉到 3.3V。

### 烧录与串口

烧录和命令继续使用板载 CP210x 的 COM3。主固件已关闭 USB Serial/JTAG
诊断，以免占用摄像头的 GPIO19/20；UART0 日志使用 GPIO43/44 对应的 CP210x。

## 视觉处理流程

1. USB Host 接收 640×480 MJPEG 帧；
2. JPEG 解码时直接按 1/8 缩放为 80×60，避免保存全分辨率像素；
3. 摄像头已物理正置，软件直接使用原始画面方向；
4. 只分析原始画面横向 25%～75%、纵向 60%～93% 的车前近端中央窗口，排除
   赛道两侧的深色背景；
5. 根据亮度直方图生成自适应黑色阈值；
6. 找出最大的连续黑色带，计算中心、宽度和黑色占比；
7. 使用亚像素加权中心，并根据黑线居中后的35个静态样本加入 `+37` 安装补偿，
   再映射成虚拟 `L/LC/RC/R`，继续调用原巡线控制器；
8. 足够宽且黑色占比足够高的横线映射为 `1111`，供原终点状态机使用。

裁剪窗口按中心位置均分为五个转向区：`<-600` 为最左、`-600～-200`
为偏左、`-200～200` 为直行、`200～600` 为偏右、`>600` 为最右。
直行区宽度覆盖窗口约20%，用于吸收80×60分析尺寸下的单像素量化抖动。

识别参数位于 `main/app/app_config.c` 的 `camera_line`，纯视觉算法位于
`main/control/camera_line_vision.c`，USB/JPEG 驱动位于
`main/drivers/camera_line_sensor.c`。

## 安全规则

- 上电默认 `IDLE`，电机停止；
- 摄像头没有产生新鲜识别帧时，BOOT 和串口 `f` 不会启动自动模式；
- 自动运行中超过 350 ms 没有新解码帧，主控制器进入故障并关闭电机；
- 第一版相机巡线速度已保守降为：直线 240、普通弯 190、边缘 160、失线
  搜索 240；
- RESET/EN 是现场物理急停；不要按住 BOOT 再按 RESET，除非有意进入下载模式；
- 第一次地面测试应架空驱动轮核对方向，再以足够空旷的场地低速测试。

## 预览说明

主巡线固件不启动 Wi-Fi 预览，以减少 CPU、内存和无线任务对 20 ms 电机控制
周期的影响。需要重新检查镜头方向和视野时，可烧录
`experiments/camera_wifi_preview`；该实验固件会锁止所有电机。
