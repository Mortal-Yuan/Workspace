### 1.4 引脚占用注意事项

- GPIO0 是板载 BOOT 按键；当前程序将其作为只启动按键。开发板 RESET/EN 是硬件复位而不是可读取的普通 GPIO，单独按下会复位 MCU，程序重新启动时首先把三路电机命令清零，因此作为物理终止键。不要按住 BOOT 的同时按 RESET，否则会进入下载模式。
- GPIO41、GPIO42 已用于左轮编码器，不能再用于早期规划中的 MPU6500 I2C。
- GPIO14 已用于后轮 `BIN1`，不能再用于早期规划中的 DHT11。

## 3. 巡线算法升级记录

### 3.1 基础比例巡线

四个传感器从左到右使用权重 `-6、-2、+2、+6`。检测到黑色的探头参与加权平均，得到负数表示线在左侧，正数表示线在右侧。A/C 两轮围绕已确认的前进组合做差速修正，B 后轮保持停止。

这个版本结构简单，普通直线和缓弯表现稳定。全白时根据最后一次非零误差选择原地搜索方向。

### 3.2 速度和丢线恢复实验

针对直线过快、弯道过快和冲出赛道后只会原地旋转的问题，曾尝试：

- 区分直线速度和弯道速度。
- 加入 PD 控制。
- 全白后执行倒车弧线、正向弧线、反向扩展搜索等多阶段恢复。

这组方案改善了部分丢线场景，但状态多、现场变量多，难以判断异常来自控制算法还是红外光照与机械摩擦。

### 3.3 专用锐角状态机实验

曾为单侧外探头持续触发增加专用锐角状态：连续确认后先短距离前进，再原地旋转，直到中心探头重新检测到黑线。

实车结果：遇到弯道时容易迅速冲出，然后进入原地旋转；降低速度后仍没有明显改善。因此已经撤回这套前冲、固定旋转和多阶段恢复逻辑，回到基础比例巡线作为对照基线。

### 3.4 当前方向锁存实验

观察到锐角处可能出现以下序列：真实路线应向左，但左侧探头先离开黑线，右侧探头短暂保留黑色，基础算法会把最后方向改写为右；随后 `0000` 丢线便向错误方向搜索。同一弯角从相反方向驶入时，传感器离开黑线的先后顺序不同，因此可能出现一侧正常、另一侧异常。

当前实验方案：

- 使用独立的 `locked_direction` 保存已确认方向。
- 相反方向必须连续出现 3 个控制周期，也就是约 60 ms，才允许改变锁存方向。
- 未确认的相反读数只记录为候选，电机继续采用锁存方向。
- 仅一侧有黑色信号时降低速度并限制最大电机命令。
- `0000` 时只按锁存方向搜索。
- 避障结束后不再把搜索方向写死为右侧。
- 日志增加 `error`、`control`、`lock`、`candidate` 和 `lost`，区分原始观测和实际控制方向。

阶段性实车结果：初次测试时效果不佳，仍出现锐角通过不稳定和同一弯角双向驶入表现不一致的现象，因此当时不能判定问题已经解决。

后续扩大实车测试范围后的最新结论：当前方向锁存、连续 3 周期确认和单侧边缘降速方案能够处理绝大多数锐角弯道，整体表现已经满足当前任务需求。少数特殊进入角度仍可能产生不理想的转向或搜索行为，应记录为后续优化点，而不是当前必须修改或阻塞后续功能开发的问题。

## 4. 已遇到的问题和处理结果

| 问题 | 分析 | 已采取措施 | 当前结论 |
| --- | --- | --- | --- |
| 轮子最初不转 | 曾出现电机外部电源未开启 | 确认电源、STBY 和单轮测试 | 三路电机均可工作 |
| 三轮位置不明确 | 早期文档与实车位置不一致 | 逐个运行 A/B/C 实车辨认 | A 右、B 后、C 左 |
| 前进时左转 | 左轮方向与 A 轮组合相反 | 修正 C 轮方向 | `A=-speed,B=0,C=-speed` 已确认前进 |
| 红外左右顺序混乱 | OUT 编号与物理排列相反，且低电平有效 | 逐路覆盖黑白纸确认，程序归一化 | 日志统一为 `L,LC,RC,R`，1 表示黑 |
| 红外全黑/全白无法区分 | 模块阈值和现场光线影响输出 | 调整模块后重复确认 | 基础识别可以工作，仍受环境影响 |
| 直线和转弯速度不合适 | 同一速度无法兼顾直线与急弯 | 分开设置直线、普通弯和边缘速度 | 普通路线表现改善 |
| 全白后无法回线 | 单纯原地旋转不能改变传感器位置 | 尝试多阶段位移恢复 | 部分场景改善，但复杂度和不确定性过高，已回退 |
| 锐角转向不足 | 连续比例控制面对大角度航向误差能力有限 | 尝试专用锐角状态机 | 前冲后旋转表现不稳定，已回退 |
| 锐角可能反向搜索 | 传感器离线顺序可产生短暂反向误差 | 使用 3 周期方向锁存和边缘降速 | 绝大多数锐角已可稳定通过；特殊进入角度保留为非阻塞优化点 |

## 5. 可选优化点

锐角处理当前已经满足主要任务需求，以下工作只在后续需要进一步提高极端场景鲁棒性时开展，不属于必须修改项：

1. 采集同一个特殊锐角从两个方向驶入时的完整 20 ms 原始模式序列，而不只观察 10 Hz 日志抽样。
2. 进一步区分“线在车体哪一侧”和“新路线实际转向”，避免只依赖最近横向误差推断锐角拓扑。
3. 验证传感器阵列相对车体前沿的位置、离地高度、探头间距和黑线宽度对极端锐角可观测性的影响。
4. 如需继续修改算法，先保存可重复的失败日志，再比较模式序列识别或加入编码器短时里程约束等方案。

当前版本已经编译并烧录成功。最新实车结论是：方向锁存方案对绝大多数锐角弯道足够有效，少数边缘场景作为可选优化点保留，不阻塞当前项目进度。

## 6. 2026-08-26 绕板避障第一版安全实现与烧录记录

本次根据《下一阶段：绕木板避障与定向回线方案》移除了旧的“近障后固定右转，看到远距离就恢复巡线”逻辑。由于当前没有已经验证的 MPU6500、MG90S 扫描机构和三轮全向里程标定，程序没有用定时矩形路线冒充完整绕板，而是先实现可安全烧录的传感器与状态机基础：

- HC-SR04 中断按 GPIO13 的实际高/低电平分别识别 Echo 上升沿和下降沿。
- 测距结果带 `VALID / OUTLIER / LOST` 质量状态，使用 3 点中值，并对超过 150 mm 的突跳做连续样本确认。
- 巡线启动后先进入 `SENSOR_CHECK`，未经 3 个连续可靠测距样本不会驱动车轮。
- 障碍阈值已根据当前场地由 230 mm 调整为 100 mm，必须由 3 个连续可靠近距样本确认。
- 确认障碍后进入 `STOP_RECORD`，停车并保存红外图案、距离和 A/B/C 编码器计数。
- MPU6500 航向、MG90S 前/侧扫描和全向里程未完成接线与标定时，进入 `HARDWARE_INTERLOCK` 并保持停车，不再使用超时强行恢复。
- GPIO43/44 的现有 UART0 诊断改动被保留；诊断增加原始/滤波距离和质量状态。

编译环境为 ESP-IDF 5.4.4，应用镜像 `build/smart-car-test.bin` 大小为 239536 字节。开发板实际枚举为 CP210x `COM3`，识别到 ESP32-S3 revision v0.2；使用 460800 bit/s 完成 bootloader、partition table 和应用烧录，三段均通过哈希校验。

烧录后只读取日志，没有发送任何电机运动命令。8 秒 UART0 诊断持续得到：

```text
ULTRASONIC quality=LOST raw=8113..8115mm filtered=-1mm age=-1ms echo=1 waiting=0 timeouts=持续增加
```

首次日志表示 GPIO13 Echo 长时间处于高电平，并形成约 8.1 m 的无效脉宽；程序正确判定为 `LOST` 并保持停车。随后确认该次检测时超声波发射/接收头正贴在桌面上，属于声学通道被遮挡或进入近场盲区，并非普通测距姿态。将探头恢复正常朝向后连续复测 10 秒，全部样本均为 `VALID`，原始距离为 231～263 mm，空闲 Echo 为低电平，超时计数始终为 0，因此 GPIO13 接线和当前 3.3 V 供电方式可正常工作。模块当前由 3.3 V 供电，Echo 直接连接 GPIO13；如果后续改为 5 V 供电，必须重新加入合适的 Echo 分压，不能让 5 V 电平直接进入 ESP32-S3。

## 7. 2026-08-26 巡线提速与绕板一体化状态机

针对板面摩擦下转弯轮容易落入电机死区、确认障碍后旧安全版只停车的问题，本次完成以下修改并烧录：

- 直线速度由 320 提高到 420，普通弯由 220 提高到 300，单侧边缘由 170 提高到 260，全白搜索由 280 提高到 360。
- 全局可调速度上限默认值由 400 提高到 500，避免420直线基准再次被旧上限裁剪为400。
- 普通弯/边缘命令上限分别提高到 480/420；比例系数由 90 调整为 75，最大修正为 240。
- 缩放后的非零转弯轮命令增加 130/1000 最小有效值，避免内侧轮只得到 8～35/1000 而停转。
- 障碍仍需 3 个可靠样本不大于 100 mm；70 mm 为绕行过程紧急停车线。
- 避障改为 `STOP_RECORD -> TURN_RIGHT_ENTRY -> PASS_NEAR_SIDE -> TURN_LEFT_FORWARD -> PASS_BOARD -> TURN_LEFT_SEARCH -> SEARCH_LINE -> ALIGN_RIGHT -> REACQUIRE_BRAKE -> CLEAR`。
- 第一次右转由连续前方清空/边缘证据结束并记录 A/C 编码器行程；后续两次左转和最终右转均复用该行程，使程序转角代数和为零，降低回线后反向的风险。
- 近侧通过、越过木板和横穿找线距离分别使用首次转向编码器行程的 2、3、5 倍作为当前场地起始系数；远侧黑线需连续 3 个周期出现。
- 任一运动段编码器 700 ms 无有效进度、达到状态超时、或前方进入 70 mm 紧急距离均进入 `FAILSAFE` 并停车；第二次按 BOOT 或串口 `x` 可退出。

该版本只使用已确认能直行和曾用于搜索的 A/C 组合，B 后轮继续保持为 0，避免假设尚未标定的 B 方向。它是用于下一轮实车采集的第一版完整绕行状态机；必须根据 `AVOIDANCE ... ticks=...` 日志确认物理左右方向并调整 2/3/5 距离系数，不能跳过现场验证直接视为最终比赛参数。

## 8. 2026-08-26 超声波触发首次转向独立测试模式

为单独确认“检测到木板后的首次右转”是否具有正确方向、速度和转角，新增 UART0/CP210x 命令 `o`。该模式没有复制另一套简化控制，而是直接复用正式避障状态机中的 `SENSOR_CHECK -> CLEAR/STOP_RECORD -> TURN_RIGHT_ENTRY`：超声波连续 3 个可靠样本不大于 100 mm 后停车记录，等待 250 ms，再以 A=+360、B=0、C=-360 执行首次右转。前方连续清空或达到受限超时条件后保存 A/C 平均编码器行程，进入 `TURN_TEST_COMPLETE` 并保持全部电机为 0，不再执行绕板后续段。

COM3 以 115200 baud 接收 `o` 和 `x`；测试中 UART0 日志包含 `mode=TURN_TEST`、避障状态、超声波质量/距离、电机命令和 `turn_ticks`。短按 BOOT 或发送 `x` 可随时终止。测试前应先让传感器正前方距离大于 100 mm，再发送 `o`，否则当前已有的近距样本会使测试立即触发。

本版已用 ESP-IDF 5.4.4 编译并烧录到 CP210x `COM3`，应用镜像为 243664 字节，写入后哈希校验通过。烧录后的 4 秒静止检查没有发送运动命令，日志持续为 `mode=MANUAL`、`cmd=0,0,0`；超声波得到约 499～567 mm 的 `VALID` 样本，Echo 空闲为低电平且超时计数为 0。镜像 SHA-256 为 `4135CAEDF44834CFB062CB86519DE4F5A79A68362FDA3F6B5E79E8E6B2B59EDF`。

首次独立转向实测需要增加转角，因此将 `TURN_RIGHT_ENTRY` 的最短持续时间由 450 ms 提高到 650 ms，转速仍为 360/1000，最大保护时间仍为 1400 ms。该修改同时用于独立测试和完整避障；完整避障会记录增加后的实际编码器行程，并让后续两个左转和最终右转继续匹配该行程。

第二次现场调整将 `TURN_RIGHT_ENTRY` 的最短持续时间进一步设为 1000 ms；转速仍为 360/1000，最大保护时间仍为 1400 ms。

监测独立转向测试时，状态机正确进入 `TURN_RIGHT_ENTRY` 并输出 `A=+360、B=0、C=-360`，但在 1400 ms 内转向编码器行程未达到 20 tick，随后进入 `FAILSAFE`。为提高静止起转扭矩，将所有避障转向段的速度由 360/1000 提高到 480/1000；最短转向时间仍为 1000 ms，最大保护时间仍为 1400 ms。

为排除超声波状态机影响，新增串口命令 `t`，直接执行 `A=+480、B=0、C=-480` 1000 ms 后自动停车。现场执行一次得到编码器增量 `A=328、B=0、C=394 tick`，说明 A/C 两个驱动方向和两路编码器在 480/1000 下均能正常工作。此前带障碍测试进入 `entry_turn_no_encoder` 更可能由障碍摆放过近造成车体或车轮受阻，而不是电机控制命令或编码器接线失效。

根据三轮全向底盘需要后轮共同提供旋转力矩的现场判断，将转向初始组合改为右转 `A=+480、B=-480、C=-480`，左转使用完全反向的 `A=-480、B=+480、C=+480`。其中 B 负方向来自旧右转测试组合，只作为有 1000 ms 测试时限和 1400 ms 保护上限的待确认方向；正式场地使用前必须观察实际车身旋转方向并检查三轮编码器增量。

B 负方向的 1000 ms 直接测试只得到 `A=3、B=2、C=36 tick`，三轮基本处于互相抵消或堵转状态，因此否定该符号。下一次待验证组合改为右转 `A=+480、B=+480、C=-480`，左转取完全反向值。

B 正方向组合的 1000 ms 实测得到编码器增量 `A=363、B=-254、C=336 tick`，三轮均产生明显运动，不再出现 B 负方向时的互相抵消。因此当前固件保留右转 `A=+480、B=+480、C=-480`、左转 `A=-480、B=-480、C=+480`；编码器 B 的负计数只是其已接线的计数方向。车身物理旋转方向仍以现场观察作为最终确认。

为克服车辆放在实际板面后的静摩擦，三轮避障转向 PWM 由 480/1000 小幅提高到 550/1000，方向组合和 1000 ms 最短转向时间不变。

550/1000 板面直接测试完成后自动停车，但编码器增量为 `A=0、B=0、C=42653 tick`。C 轮一秒内 42653 tick 明显不可能是真实轮速，说明 GPIO41/42 编码器信号出现接触不良、悬空或电机干扰导致的高速抖动；A/B 为 0 则没有提供有效运动证据。该次数据不能用于转角标定，而且 C 的异常计数可能掩盖状态机的堵转判断，继续完整避障测试前应结合现场观察检查 C 编码器接头和线束。

现场直接观察确认 B 后轮在 `B=+550` 时物理方向与目标右转相反，因此撤销仅依据“编码器有计数”作出的 B 正方向判断。当前右转修正为 `A=+550、B=-550、C=-550`，左转为完全反向的 `A=-550、B=+550、C=+550`。编码器正负号只表示接线计数方向，不能代替车轮物理方向判断。

为重新评估板面上的最低可用力度，三轮转向 PWM 从 550/1000 降至 420/1000；测试组合为 `A=+420、B=-420、C=-420`，持续 1000 ms 后自动停车。

420/1000 板面直接测试得到三轮编码器增量 `A=635、B=647、C=656 tick`，三轮行程高度一致，未出现堵转或单路高速噪声。测试后命令自动恢复 `0,0,0`。结果表明正确的 B 物理方向对旋转效果比继续提高 PWM 更关键，当前固件保留 420/1000 作为避障转向速度。

随后完成一次带超声波触发的独立避障测试：木板在 74 mm 被确认后进入 `STOP_RECORD`，然后以 `A=+420、B=-420、C=-420` 进入 `TURN_RIGHT_ENTRY`。转向过程中前方测距由近障变为 353 mm、289 mm，最终在前方清空后进入 `TURN_TEST_COMPLETE`，保存 A/C 平均转向行程 `595 tick`，电机命令恢复 `0,0,0`。主机随后发送 `x`，该次“测距触发—刹车—三轮右转—自动停车”独立链路验证成功。

因 1000 ms 最短转向对应的实际角度过大，将 `TURN_RIGHT_ENTRY` 最短持续时间降为 500 ms。420/1000 三轮 PWM、250 ms 刹车和 1400 ms 最大保护时间不变；独立避障仍需满足连续前方清空证据，因此 500 ms 是最短值而非无条件固定截断时间。

500 ms 独立避障测试从约 44～45 mm 近障进入三轮右转并到达 `TURN_TEST_COMPLETE`，电机随后停车；但保存的 `turn_ticks=4681` 远高于此前 1000 ms 直测约 635～656 tick 的量级，属于编码器干扰，不可作为真实转角。转动期间超声波也短时出现 `OUTLIER/LOST`、Echo 高和累计超时；发送 `x` 后静止复查恢复为约 566～583 mm 的连续 `VALID` 样本、Echo 低且超时计数清零，说明异常集中在电机转动期间。完整绕板前需处理电机干扰和编码器毛刺，否则错误的首次转向行程会被后续各段复用。

按现场要求将三轮避障转向 PWM 从 420/1000 降到 100/1000，右转为 `A=+100、B=-100、C=-100`，最短转向时间保持 500 ms。该值低于此前板面有效转动的测试范围，预计可能落入静摩擦死区，需通过受限测试确认。

上述 100/1000 版本因 CP210 串口写入超时没有完成烧录，随后现场澄清真正目标是“检测到障碍后右转约 30°”，而不是将 PWM 降至 100。故撤销 100/1000，恢复板面验证有效的三轮 420/1000。结合一次过大转向保存的约 595 tick，将 30°第一版目标设为 300 tick；转向不再等待超声波完全离开木板边缘，而是在至少 200 ms 后达到 300 tick 即停车/进入下一状态，1400 ms 未达到则 `FAILSAFE`。行程由 A/B/C 三轮绝对增量的中位数计算，避免单路（此前主要为 C）毛刺提前结束转向。该 300 tick 与 30°的对应关系仍需本轮实车确认。

300 tick 独立测试虽然进入 `TURN_TEST_COMPLETE`，但保存值跃升到 1917 tick，说明转动期间至少两路编码器同时受干扰，中位数仍会被毛刺提前触发。为避免原始编码器噪声决定角度，首次右转最终改为经过现场起始标定的 `A=+420、B=-420、C=-420` 固定 500 ms；后续反向/同向转弯也固定为对称的 500 ms。300 tick 只保留为前进距离的临时比例参考，不再作为转向结束条件。

固定 500 ms 版本通过 57600 baud、no-stub 方式完整恢复烧录并通过三段哈希校验。随后独立避障在约 29～32 mm 触发，进入 `TURN_RIGHT_ENTRY` 后输出 `A=+420、B=-420、C=-420`，500 ms 到时无条件进入 `TURN_TEST_COMPLETE` 并将命令清零；主机随后发送 `x`。日志显示的 `turn_ticks=300` 是供后续距离系数使用的固定参考值，不是本次受干扰的原始编码器实测值。实际是否为 30°仍以现场观察确认。

按现场进一步标定要求，将所有三轮转向固定时间从 500 ms 降为 100 ms，PWM 和方向组合保持不变。该值对应的实际角度需重新进行现场确认。

100 ms 版本已完成编译并烧录到 CP210x `COM3`，应用镜像为 243792 字节。由于本次 CP210 长时间连续传输会中途断流，先以 256 字节 ROM 写块和每块 50 ms 间隔恢复并校验 bootloader、partition table，再将应用镜像按 4 KB Flash 扇区分为 60 段独立写入；60/60 段均在首次尝试通过哈希校验。启动后只进行了 6 秒静止检查，没有发送 BOOT、`o` 或 `t` 等运动命令；UART0 持续显示 `mode=MANUAL`、`cmd=0,0,0`、超声波 `quality=VALID`，实测原始距离约 500～607 mm、Echo 空闲且超时计数为 0。由此确认固件已完整启动并保持安全停车，100 ms 对应的实际右转角度仍需现场触发观察。

根据新的现场路径定义，100 ms 入场右转之后不再按固定编码器距离使用 A/C 向前通过近侧，而是进入 `STRAFE_RIGHT_FIND_EDGE`：右轮 A 停止，后轮 B 与左轮 C 暂按 `A=0、B=-420、C=-420` 向木板右侧移动。状态机必须先连续 2 个有效样本重新看到木板，之后才允许把连续 3 个“大于动态可见距离上限”的有效样本或 Echo 低电平的 `LOST` 事件判为板边；并要求至少已经横移 250 ms，避免把转向时的瞬时超声波丢失误判为边缘。确认板边后保持相同横移动作 300 ms，使车身而不只是传感器越过近角，再依次恢复前进航向、越过木板、转向搜索远侧黑线、连续 3 次确认黑线并恢复原航向。未重新看到木板、横移无编码器进度、4 秒内找不到边缘、后续前方小于等于 70 mm 或找不到黑线都会进入 `FAILSAFE` 停车。该逻辑已通过 ESP-IDF 编译，应用镜像为 244544 字节，但尚未烧录；B/C 横移的物理方向、100 ms 对应的 30°和 300 ms 角点余量仍需分段实车校准。

根据第三轮现场要求进一步调整控制：巡线直线、普通弯、单侧边缘和全白搜索分别由 420/300/260/360 降为 380/270/230/320，默认速度上限由 500 降为 450；绕行平移、B/C 找边横移和远侧找线分别降为 310/380/270，三轮转向继续保持已经能克服静摩擦的 420/100 ms，避免把速度修改与 30°标定混在一起。障碍触发距离由 100 mm 提高到 200 mm，并增加 `STOP_CONFIRM`：行驶时只要本次真实 Echo 脉冲的原始距离首次小于等于 200 mm，哪怕该跳变尚未通过中值/异常值滤波，也立即把三轮命令清零；停车后再等待两个新的超声事件，只有两次都包含小于等于 200 mm 的真实回波才进入 `STOP_RECORD`，否则回到 `CLEAR` 恢复巡线，Echo 卡高则进入 `FAILSAFE`。BOOT 改为只启动，运行中再次按下不停止；RESET/EN 无法由固件作为 GPIO 读取，但单独按下会硬件复位，程序启动路径首先关闭并清零电机，因此将 RESET 作为物理终止键，串口 `x` 仍可软件停车。不要按住 BOOT 同时按 RESET，以免进入 ROM 下载模式。

上述版本已通过 ESP-IDF 编译并烧录到 CP210x `COM3`，应用镜像为 245280 字节，SHA-256 为 `BABD6821B8D60FDC35797CCA6128FED3E8520243750E1C6B7A3027CAEC8A6EAF`。针对该接口的长传输不稳定问题，应用仍按 4 KB 分为 60 个扇区，以 256 字节 ROM 写块、每块间隔 50 ms 的方式独立写入；60/60 个扇区均在首次尝试通过哈希校验。硬复位启动后只读取了 6 秒静止日志，没有按 BOOT 或发送运动命令；日志持续为 `mode=MANUAL`、`cmd=0,0,0`、`confirm=0:0`，超声波得到约 295～303 mm 的 `VALID` 样本、Echo 低且超时计数为 0，确认新版已经运行并保持停车。

## 9. 2026-08-26 巡线启动增力与硬件按键重构

针对板面静摩擦导致低速起步和转弯内侧轮容易停住的问题，当前源代码在不使用受干扰编码器的前提下增加了短时开环启动增力。巡线 A/C 轮从静止开始运动或命令反向时，如果目标绝对值低于 420/1000，则先输出 420/1000、持续 100 ms，之后自动降回原巡线目标；连续零命令达到 120 ms 后才允许同方向再次增力，避免传感器抖动反复触发。普通弯与单侧边缘缩放后的非零最小命令同时由 120 提高到 170/1000。该增力只接入巡线、转弯修正和丢线搜索，不改变已经实测过的避障三轮 420/1000、100 ms 转向参数，也不宣称实现了“恒速增扭矩”。

按键审查确认旧实现存在两个可靠性问题：一是上电后的固定冷却窗口会吞掉早期有效按压；二是避障进入故障停车后仍可能保留运行标志，使 BOOT 被当成“已经运行”而忽略。重构后 BOOT 使用原始电平、稳定电平和释放重装三个阶段：按压需稳定 50 ms，释放需稳定 80 ms 才重新允许下一次事件，上电保护期为 500 ms；保护期内出现的有效短按会排队到期后执行，而上电时已经按住 BOOT 则必须先释放再按，防止误启动。顶层不再使用容易组合矛盾的多个布尔量，而采用互斥的 `IDLE/RUNNING/TURN_TEST/FAULT` 模式；正常运行中 BOOT 仍是只启动、不切换，故障停车后 BOOT 可执行完整安全重初始化。启动日志和实时诊断新增 BOOT 原始/稳定/已装填状态与顶层模式，便于复现实物按键问题。

RESET/EN 是 ESP32-S3 的硬复位输入，固件无法把它当作普通 GPIO 读取；单独按 RESET 会立即停止当前程序并重新启动。为缩短复位相关风险，所有三轮零命令现在同时拉低电机驱动 EN/STBY，非零命令只在方向与 PWM 均写好之后才使能驱动。若要求在固件尚未启动或误入 ROM 下载模式时也保证电机关闭，还应在驱动 EN/STBY 上增加约 10 kΩ 外部下拉（前提是驱动板未自带）；这是软件无法覆盖的硬件安全窗口。BOOT 是启动绑带脚，因此仍禁止按住 BOOT 的同时按 RESET，否则可能进入下载模式。本次源代码已通过 ESP-IDF 5.4.4 完整编译，应用镜像为 246544 字节，SHA-256 为 `71A2D2FC311E67ED31A646184CCDAA6E004CD5BE4CF725BEDFFA3469EE6A8CC1`。随后使用 ESP32-S3 ROM、no-stub、115200 baud 将 bootloader、分区表和应用完整烧录到 CP210x `COM3`，三段均通过 Flash 哈希校验并自动硬复位。烧录后只读取约 8 秒静止日志，没有发送任何运动命令：顶层持续为 `IDLE`，电机命令 `0,0,0`，增力状态 `0,0`，BOOT 原始/稳定/装填状态为 `0/0/1`。当前超声波大多数样本为约 2168～2197 mm 的 `VALID`，但远距离反射环境中间歇出现 `OUTLIER/LOST`、Echo 高及超时，随后可恢复；启动后的 `SENSOR_CHECK` 仍会要求连续可靠样本后才允许运动。

## 10. 2026-08-26 临时避障逻辑简化为停车等待

为给后续重新设计绕板方案留下清晰基础，当前版本完整移除了自动右转、B/C 横移、编码器距离段、越板、找线、航向恢复和相应超时分支，避障只保留 `SENSOR_CHECK -> CLEAR -> WAIT_CLEAR -> CLEAR`。启动巡线后，`SENSOR_CHECK` 先保持停车并取得连续 3 次无障碍观测；`CLEAR` 中遇到 20～200 mm 的第一帧真实 Echo 原始回波会立即将三轮命令清零并进入 `WAIT_CLEAR`，无需等待该近距突变通过中值或跳变滤波。停车后持续测距，只有连续 3 个“障碍不存在”观测才恢复巡线；可靠回波的原始值和滤波值均大于 200 mm，或一次测距结束时没有回波且 Echo 为低，均可计为不存在。任何近距、无效/异常回波或 Echo 高都会把计数清零。恢复时清理巡线丢线/图样稳定计数并重新允许启动增力。旧串口 `o` 超声触发转向测试随自动转向路径删除；受 100 ms 时限约束的人工 `t` 三轮测试保留，但不会被避障自动调用。

该版本通过 ESP-IDF 5.4.4 完整编译，应用镜像为 242336 字节，SHA-256 为 `806E6B0EDCE0A45430521BD04D0B6026F3A82B10E430E0AA69029C38BE10D8B1`。随后使用 ROM no-stub、115200 baud 烧录到 CP210x `COM3`，bootloader、分区表和应用均通过 Flash 哈希校验并自动硬复位。烧录后只读取约 8 秒静止日志，没有发送 BOOT 或运动命令：模式持续为 `IDLE`，电机命令 `0,0,0`，增力 `0,0`，BOOT 状态 `0/0/1`；超声波稳定得到约 167 mm 的 `VALID` 回波。由于该物体位于 200 mm 阈值内，下一次按 BOOT 后应保持停车并进入 `WAIT_CLEAR`，可直接用于验证移开物体后三次清空恢复巡线的行为。

## 11. 2026-08-26 固件模块化重构
