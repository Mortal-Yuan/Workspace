# 2026-09-01 避障前航向对正与左移修正记录

## 1. 现场问题

本轮针对两个实车现象修改：

- 小车在近障刹停时可能仍带有巡线弯道航向，原状态机刹停150 ms后立即执行固定矩形绕障，
  导致整个绕障路径的初始姿态不一致；
- 左横移仍有轻微逆时针偏航，而且1231 ms左移距离略大。

## 2. 航向对正状态

避障顺序由：

```text
BRAKE -> STRAFE_LEFT_DISTANCE -> ...
```

改为：

```text
BRAKE -> ALIGN_HEADING -> STRAFE_LEFT_DISTANCE -> ...
```

`ALIGN_HEADING` 的控制合同如下：

- 刹停150 ms后进入，只接受进入状态之后新解码的摄像头帧；
- 使用 `camera_line_snapshot_t.heading_permille`，不使用包含横向位置项的 `steering_permille`；
- 航向误差定义为 `heading - (-383)`；误差为正时输出顺时针原地旋转，为负时输出逆时针原地旋转；
- 旋转命令取航向误差绝对值，并限制在260～300；不输出前进或横移；
- 偏离目标的新帧授权一个30 ms旋转脉冲，期间的新帧不能延长截止时间；
- `|heading - (-383)| <= 80` 时停止旋转；必须连续3个不同 `decoded_frames` 都满足阈值才开始左移；
- 相同摄像头帧被20 ms控制任务重复读取时不重复计数；30 ms脉冲结束后先停转，再等待后续新帧；
- 无有效线路、相机帧不新鲜或尚无新帧时保持零命令；
- 进入后3000 ms仍不能完成对正则进入锁存 `FAILSAFE`，不会盲目执行开环矩形路径；
- 对正期间连续3次超声波不确定事件仍沿用原安全规则进入 `FAILSAFE`。

## 3. 左移参数修正

- 左移顺时针反偏航补偿：`500 -> 550 permille`；
- 右移补偿保持500，不受本轮修改影响；
- 左移稳态车体命令仍为380，起步150 ms仍为500；
- 左移时长：`1231 -> 1170 ms`，约缩短5%；
- 前进1191 ms、右移最多960 ms保持不变。

Kiwi逆解后的典型左移电机命令变为：

| 阶段 | 修改前 A/B/C | 修改后 A/B/C |
| --- | --- | --- |
| 左移稳态380 | `-300/-570/+300` | `-300/-589/+300` |
| 左移起步500 | `-300/-750/+300` | `-300/-775/+300` |

A/C仍受纯横移最小命令300约束，本轮主要通过略微增强B后轮负向命令增加顺时针反扭矩。

## 5. 烧录状态

重新识别串口得到：

```text
COM1
COM2
COM3 = \Device\Silabser0 / USB VID_10C4&PID_EA60
```

按照项目可靠烧录流程，以115200 baud、ROM `no-stub`、ESP32-S3参数连接COM3。esptool在任何
Flash写入发生前报告：

```text
This chip is ESP32-S2, not ESP32-S3.
```

因此首次连接没有发生Flash写入。随后重新连接小车主控，同一COM3被明确识别为ESP32-S3 rev0.2、
16 MB PSRAM、MAC `9c:cc:01:fb:8f:9c`。最终标定镜像使用115200 baud、ROM `no-stub` 完整写入，
bootloader、分区表和应用三段哈希校验均通过。

无命令启动检查持续为 `IDLE`、`cmd=0,0,0`、编码器0/0/0，摄像头 `fresh=1`、`cam_err=0`。

## 6. 物理平行姿态标定

用户将小车放在正对障碍、车身与障碍摆正的位置，超声实际稳定在189～190 mm。连续静止帧为：

- `heading=-381..-384`，中位数-383；
- `center=-158..-161`；
- 摄像头持续 `fresh=1`，没有丢帧或解码错误；
- 三轮命令和编码器均为0。

因此物理平行姿态的视觉航向不是0，而是-383。本轮把-383写为独立的避障对正目标，不修改普通
巡线的中心补偿和转向公式。刷入标定版后再次静止检查，`heading=-376..-384`，稳定落在目标±80内。

## 7. 首次动态验证顺序

1. 架空车轮，确认上电为 `IDLE` 且三轮命令为零；
2. 人工相对当前物理平行姿态小角度摆出正、负误差，确认相对-383的正误差顺时针、负误差逆时针对正；
3. 确认 `heading-(-383)` 进入±80后停车，并等待3个不同摄像头帧才开始左移；
4. 遮挡线路，确认3秒后进入 `FAILSAFE` 且始终没有盲目左移；
5. 落地验证1170 ms左移距离和偏航；
6. 若仍轻微逆时针，可按550→600逐级提高左补偿；若已经顺时针过补偿，则回退到525；
7. 只有左移单段稳定后，再验证完整前进、右移找线和终点停车。

## 8. 首次动态结果与慢速点动修正

首次动态对正后，静止遥测显示超声仍为有效读数（约225 mm），没有超声超时；但摄像头航向
稳定在+26～+31，相对-383目标已经越过约409～414。原实现会在等待下一张摄像头帧期间持续
保持上一条260～420旋转命令，因此帧间延迟会造成明显过冲，并可能在原1秒窗口结束时进入
`FAILSAFE`。

本次修正不降低260的瞬时起转下限，以免三轮静摩擦导致点动不起来；改为把上限降到300，且
每个新摄像头帧只执行一个20 ms旋转脉冲，随后立即归零等待下一帧。对正超时同步从1000 ms
延长到3000 ms，使减速后的控制仍有足够时间收敛。左移、前进和右移参数保持不变。

修改后的主机回归与ESP-IDF完整增量构建均通过。COM3曾短暂返回设备不可用，重启已确认的
`USB\VID_10C4&PID_EA60\0001` CP210x设备后恢复；烧录前重新识别为ESP32-S3 rev0.2、MAC
`9c:cc:01:fb:8f:9c`，三段Flash写入哈希均校验通过。

无启动命令检查中，模式持续为 `IDLE`、`cmd=0,0,0`，超声约234～237 mm且 `q=1`，摄像头
持续新鲜。清零编码器后，三个计数仍在零电机命令下以每0.5秒数万的速率增长，远超真实机械
转速，确认是当前未上拉、未滤波编码器输入的电气干扰；它不代表电机在转，但编码器数据暂时
不能用于避障闭环。本次仅调整航向点动，不把编码器驱动改动混入该标定版本。

## 9. 点动时长改为100 ms

根据第二次现场要求，单次航向修正由20 ms提高到100 ms，命令范围仍为260～300，对正总超时
仍为3000 ms。由于摄像头约15 FPS、帧间隔约67 ms，不能简单让每一帧重新计时，否则100 ms
脉冲会永久重叠并退化为持续旋转。当前实现固定单次截止时间：脉冲期间的新帧可以根据最新
航向让电机提前停止或改变方向，但不能延长截止时间；截止后消费当前最新帧并输出零命令，
只有再到达一张更新的摄像头帧才允许开始下一次100 ms脉冲。

主机回归和ESP-IDF构建均通过。烧录前COM3再次确认是ESP32-S3 rev0.2、16 MB PSRAM、MAC
`9c:cc:01:fb:8f:9c`，三段写入哈希均校验成功。无启动命令检查连续保持 `IDLE`、
`cmd=0,0,0`、编码器 `0,0,0`；相机 `fresh=1`、`cam_err=0`，超声为有效读数，没有进入
`FAILSAFE`。

## 10. 点动时长回调为30 ms

根据第三次现场要求，当前单次航向修正由100 ms回调为30 ms；旋转命令260～300、目标-383、
允许误差±80、连续3帧确认和3000 ms总超时均保持不变。脉冲仍使用固定截止时间，不能被
相机新帧延长；脉冲结束后等待后续新帧再开始下一次修正。

主机回归和ESP-IDF构建通过；COM3重新确认为同一ESP32-S3后完成三段烧录及哈希校验。无启动
命令检查持续为 `IDLE`、`cmd=0,0,0`、编码器 `0,0,0`，相机无解码错误，超声约254～255 mm
且质量有效，没有进入 `FAILSAFE`。30 ms镜像SHA-256为
`54A0DF521FD8D153F9E9CB418B7EC0A8359930FDCFA819FD93BA71113AF016BB`。

## 11. 实车撤销障碍前对齐

实时串口测试中，小车到达障碍前执行了一次航向旋转，随后状态锁存在 `obstacle=12`（即
`FAILSAFE`），三轮命令归零。此前接线过程中还捕获到一次用户未主动触发的 `POWERON` 复位，
供电或接线瞬断需另行排查。按现场要求，本次从活动固件中彻底删除 `ALIGN_HEADING` 状态、转换、
全部对齐配置、运行时字段和对应测试，不保留“设为0”的旁路实现。避障顺序恢复为：

```text
BRAKE -> STRAFE_LEFT_DISTANCE -> SETTLE_FORWARD -> FORWARD_DISTANCE
      -> SETTLE_RIGHT -> STRAFE_RIGHT_DISTANCE -> LINE_CONFIRM
```

`BRAKE` 仍保持150 ms，结束后同周期直接输出左移起步命令；左移1170 ms、前进1191 ms、右移
最多960 ms以及横移补偿均保持不变。

最终复核时又删除了对齐功能曾引入的完整摄像头快照参数和主机测试辅助函数；避障监督器接口恢复为
只接收四路虚拟线路采样。源码检索已无 `ALIGN_HEADING`、`align_`、`HEADING_ALIGNED` 或
`obstacle_camera` 残留。主机回归和ESP-IDF构建通过，最终镜像大小为364880字节（`0x59150`），
SHA-256为 `0DB9BE4A7E5116F6638AFCCAD729751CDB45E44297A5053D649E4C5E454009A9`。

烧录前COM3再次识别为ESP32-S3 rev0.2、16 MB PSRAM、MAC `9c:cc:01:fb:8f:9c`；三段Flash
写入哈希全部校验通过。最终无命令检查始终保持 `IDLE`、`obstacle=0`、`cmd=0,0,0`、编码器
`0,0,0`；摄像头持续新鲜且无解码错误，超声波约329～337 mm、质量 `q=1`（有效）。
