## 2. 主程序调用链

主入口和控制关系如下：

```text
app_main
  → app_controller_init
  → 20 ms 控制任务
      → ultrasonic_step                 采集超声波
      → camera_line_sensor_snapshot     读取最新视觉快照
      → start_button / UART             处理启动、停车和人工命令
      → 摄像头新鲜度与故障检查
      → obstacle_supervisor_step        仲裁避障、终点和故障
          ├─ BLOCK：输出零，保持停车
          ├─ LINE_FOLLOW：未完成入场动作时调用 startup_maneuver_step
          │              完成后才调用 line_follow_step
          └─ OVERRIDE：用 kiwi_kinematics_inverse 生成绕障动作
      → motor_driver_apply              唯一一次最终电机输出
```

控制模式包括 `IDLE`、`AUTONOMOUS`、`MANUAL`、`SELF_TEST` 和 `FAULT`。
自动模式在等待巡线或正常巡线时，摄像头快照超过350 ms没有更新会在同一控制周期进入 `FAULT`
并停车；该故障被标为“本次开机不可恢复”。一旦近障触发 `BRAKE`，后续改为固定动作，不再用线路
输入，因此摄像头新鲜度不再中断本轮避障。串口停车命令只会继续保持 `FAULT`，必须硬件复位或
重新上电后再开始。

BOOT 键 GPIO0 是低有效启动键，带 50 ms 消抖、80 ms 释放重装和 500 ms 上电保护，只负责启动，
不作为停车键。板上的 RESET/EN 是硬件复位。串口 `f` 可启动，`x` 可停车；人工方向命令会退出
自动模式。

串口 `t` 和 `y` 分别执行100 ms、420强度的三轮纯右自转和纯左自转短测：右转
`A=+420,B=-420,C=-420`，左转完全反向；到时自动恢复 `IDLE` 和零输出。

## 3. 摄像头采集与视觉算法

### 3.1 摄像头输入

- UVC 设备 VID:PID：`349c:3307`。
- 主程序固定请求 MJPEG 640×480 @ 15 FPS，流接口索引为 0。
- USB D- 接 GPIO19，D+ 接 GPIO20，摄像头供电为 5V 和 GND。
- 使用 3 个 512 KiB PSRAM 帧缓冲和 3 个 10 KiB URB；队列只保留一帧，来不及处理时丢弃旧工作，
  避免控制链堆积越来越迟。
- 最新源码及开发板当前固件将JPEG按1/8解码为80×60 RGB888。红球处理完整解码帧，巡线入口处理
  下半幅80×30；只读实测处理速度接近15 FPS。
- 当前采用摄像头原生方向，`rotate_180=false`。

### 3.2 有效画面和二值化

解码后把完整80×60画面交给视觉模块，再应用 ROI。当前主要分析区域为：

- 横向：25%～75%；
- 纵向：46.7%～79.7%；
- 对80×60解码图为 `x=20..59`、`y=28..46`；相对原 `y=36..54` 整体上移8像素，高度保持19行。

RGB 转灰度使用近似权重 `77R + 150G + 29B`。灰度直方图取第 2 百分位作为暗端、第 90 百分位
作为亮端；对比度小于 30 时，本帧仍是有效相机帧，但报告“未检测到线”。否则使用
`min(Otsu + 对比度/8, 120)` 作为黑色上限。小于等于阈值的像素才作为黑线，避免灰度不够低的
阴影被 Otsu 暗类误判成赛道黑线。

### 3.3 连通区域与线路几何

- 使用真正的二维八邻域 BFS 连通域。
- 当前普通线路没有最小面积、必须触底、最小高度、最大宽度、首次中心范围或历史最大跳变等
  硬门槛；只要连通区域非空就有资格成为候选。
- 没有可靠历史时选择面积最大的候选。
- 连续得到 3 帧普通线路后建立可靠历史；有历史时采用软评分：面积越大越好，近端中心和转向量
  越接近历史越好。它只降低偏离候选的分数，不硬拒绝急弯；画面只有一个候选时仍会接收。
- 宽终点形状不更新普通线路历史，避免终点污染下一帧的候选选择。

每个候选按图像Y坐标直接划分近远：组件Y跨度中靠近画面底部的三分之一平均为近端，靠近画面顶部的
三分之一平均为远端。这是9.1的行分段方法，不沿连通黑线计算测地路径；因此发卡弯的返回支若同样回到
画面底部，可能参与近端平均。结构中保留的近/远Y字段只为兼容后续USB预览数据格式，不参与巡线决策。
中心位置按千分比缩放，再加入 `-165` 的摄像头中心补偿。定义：

```text
heading = far_center - near_center
steering = near_center + 0.5 × heading
```

若近、远端跨越画面中心，并且 `|near| >= 160`、`|heading| >= 300`，判为发卡急弯，方向项增益
降为 0.1，防止远端黑线把近端转向过度拉偏。视觉内部限制到 ±2000，发布给控制器前限制到 ±1000。

新接受的普通线路会与上一份已发布快照平滑：中心值采用 `(2×旧值 + 新值)/3`，再重新计算转向。

### 3.4 虚拟四路巡线信号

为了复用原来的离散巡线控制，连续转向量被映射成四个虚拟传感器：

| 连续转向量 | 虚拟状态 | 含义 |
| ---: | :---: | --- |
| `< -600` | `1000` | L |
| `-600..-201` | `0100` | LC |
| `-200..200` | `0110` | LC + RC，居中 |
| `201..600` | `0010` | RC |
| `> 600` | `0001` | R |
| 无线路 | `0000` | 丢线 |
| 宽 T 形候选（运行时终点门禁关闭） | 按普通方向位输出 | 普通线路 |

代码保留了宽度至少占 ROI 800‰、面积至少占 200‰ 的 T 形候选分类和两帧确认能力，另有仅限
`IDLE` 使用的串口 `p` ASCII 摄像头视图。但当前自动运行始终关闭终点门禁，T 形、宽线和
`1111` 都按普通线路处理，不能触发停车。终点由绕障完成后的固定 525 ms直行计时产生。

### 3.5 红/蓝目标识别与独立入夹模式

最新源码将同一张80×60 RGB888图并行送入 `camera_ball_vision`。目标检测扫描整幅解码图，不受黄色巡线ROI限制，
且不改变巡线或避障控制；只有用户从 `IDLE` 显式发送 `b` 时才进入独立 `BALL` 电机模式。第一层弱红门限为R至少45、比G/B较大者至少高8、占RGB总量至少
380‰，用于保留偏暗、偏淡的球边缘；但弱红不能独立成球。原80×60配置要求每个有效连通域至少4个
“强红种子”，强红要求R比G/B较大者至少高40且占RGB总量至少420‰，强种子还需占有色像素至少80‰。
蓝色使用B至少70、比R/G较大者至少高16、占RGB总量至少390‰的弱门；强蓝种子要求色差至少45且比例至少430‰，
区域平均B还需比R/G较大者至少高55。两种颜色互不连通，颜色切换会重新开始稳定帧计数。

为修复表面高光，算法严格限制为两轮同色局部多数扩张：最大通道至少160、通道极差不超过48且目标色
没有比最大通道低超过12的高亮像素，只有在周围至少3个像素属于同一目标色时才补入。高光像素不能建立新
连通域，也不计入区域平均RGB，所以白色物体不会自行成为目标，白色反光也不会拉低目标色均值。
修复后的八邻域连通域仍需满足：普通目标面积至少占整帧4‰（80×60约20像素）、包围盒填充率至少350‰、
至少4个强色种子，并留出2像素图像边距。红球短边/长边至少600‰；实测蓝色矩形约12×5像素，蓝色门限放宽到350‰。
合格目标优先于未通过区域，
同类区域再按颜色、强种子比例、面积和形状综合置信度选择。球心X/Y各移动不超过200‰的同色候选连续
3帧后才置 `detected=1`。40 cm标定点另有受限远距门：面积2～3‰且置信度至少900时允许成为候选，
但必须连续5个新画面才确认；4‰以上仍按原来的3帧确认。

串口 `BALL=color/candidate/detected/stable_frames` 中红色编号为2、蓝色编号为3；`bseed=强色数/高光补入数` 和
`bbox=左/上/右/下` 用于现场调试；最新源码四项均为0～1000的归一化坐标。实时窗口在缩略整幅画面绘制标记：橙框表示尚未连续确认的候选，洋红框
和球心表示已经连续确认的目标，框可以出现在黄色巡线ROI之外。2026-09-01旧算法曾稳定识别平均RGB约
`160/97/90`的真实红球，并用40的区域平均红色优势抑制过均值约`98/74/47`的弱红背景；新算法改由
强红种子保护背景抑制，同时允许弱红边缘和局部白色高光加入球体。

独立 `ball_approach` 控制器不限定红蓝颜色，使用当前评分最高的已确认目标；启动后先左扫800 ms、停车150 ms，再右扫1600 ms并循环。发现候选立即停车，
确认后以80 ms A/C短脉冲和120 ms停车画面把球对到 `center_x=+25`；连续3帧误差不超过60‰才开始前进。
接近速度按球的 `center_y` 从300降到250和210，前进起步增力为360并保持100 ms。此前降低30%的
210/175/147/252实验因无法可靠克服静摩擦而撤回；搜索和对齐速度不变。误差超过180‰就先停车重新对齐。根据P0/P10实测，
`center_y>=790`、`bbox_bottom>=880‰`，且高度至少170‰或面积至少18‰才视为入夹：首帧满足立即零输出，
第二个静止新画面仍满足才锁存 `BALL_DONE`。摄像头过期、单次接近超过12秒或总流程超过30秒会锁存
`BALL_FAILSAFE`；`x`始终可以退出并停车。该功能尚未连接避障 `FINISHED`。当前固件现已恢复到采集P0～P40
标定时使用的80×60采样网格；仍应核对新版强红/弱红/高光分割对球框边界的影响，再进行低速地面运动验证。

## 4. 巡线控制逻辑

### 4.1 自动启动固定动作

短按 `BOOT` 或发送 `f` 后，超声波仍需先通过连续3次空旷确认。随后每次启动只执行一遍以下非阻塞
开环动作，期间 `x`、手动命令、故障和近障避障仍可抢占最终电机输出：

1. 前进1074 ms：前150 ms车体前进命令500，随后为400，对应轮命令
   `A=-speed,B=0,C=-speed`，作为约20 cm的当前标定。
2. 零输出停车150 ms，降低右轮反转时的惯性影响。
3. 以420执行纯顺时针旋转200 ms，对应 `A=+420,B=-420,C=-420`。这是上一版267 ms右转的
   四分之三（取整），开环目标角度由约80°相应降为约60°。
4. 再零输出停车150 ms，清除转向前的巡线方向和轨迹记忆，然后以最新摄像头帧开始正常巡线。

当前没有可靠陀螺仪闭环，电机运行时编码器又存在干扰，因此20 cm和约60°均由时间估算，必须以
实车尺量和角度观察继续微调。串口 `STATUS startup=0..5` 依次表示等待安全放行、前进、前进后停车、
右转、右转后停车、固定动作完成。

### 4.3 正常巡线

四路离散误差权重为 L=`-6`、LC=`-2`、RC=`+2`、R=`+6`，多个有效位取平均。初始方向必须连续
确认3次才锁定。方向锁定后，单次相反方向不会停车或进入丢线；控制误差继续保持在原锁定方向，
只有相反方向本身连续确认3次后，方向锁才切换到新方向。

有可靠连续转向且不处于反向保持时，差速修正按 `steering × 300 / 600` 计算并限制到 ±300；
否则使用离散误差乘 `Kp=120`。普通前进命令为：

```text
A = -base + correction
B = 0
C = -base - correction
```

也就是说当前接线下，正常直行是 A、C 同为负命令，B 为零。弯道和边缘情况下若命令过大，会
按比例缩到对应上限，而不是简单截断某一个轮。

只剩单个虚拟传感器时，对应内轮最低给 +100 的反转命令，帮助车头压入急弯。某个轮刚成为
主要驱动轮或发生换向，且目标绝对值达到 200 时，前 150 ms 至少给到绝对值 500，以克服静摩擦；
该增力不放大 +100 这类小内轮命令。

### 4.4 近端盲区与丢线搜索

- 新建立且 `|steering| >= 180` 的转向，会暂时保持上一份可靠巡线轨迹 180 ms；当转向回到
  80 以内释放。这用于黑线进入摄像头近端盲区时保持入弯动作。
- 若刚丢线且有可靠巡线历史，前 120 ms 沿用上一份未增力的巡线命令，之后停车到第 150 ms。
- 若开机就没有线或没有可靠历史，则完整 150 ms 都保持停车。
- 150 ms 后按9.1实现使用 `A/C` 反向、`B=0` 的搜索命令，目标绝对值为211；A/C达到增力阈值，
  首次起转或换向时会短时提升到500。该向量在Kiwi底盘上是旋转与横移的合成，不是三轮纯自转。
- 首段方向依次取已锁定方向、最近相机转向方向、最近离散误差方向；完全没有历史时才默认向左。
- 搜索腿依次为1.2、2.4、3.6、4.8、6.0、7.2秒，之后一直以7.2秒左右交替；没有总超时停车。
- 看到第一个线路候选会在同一周期停止搜索；累计任意3个含线的不同相机解码帧后恢复前进。
  重复使用同一帧不增加计数，但这3帧的左/中/右方向不要求一致。

## 5. 超声波与绕障状态机

### 5.1 超声波测距

- HC-SR04 Trig 为 GPIO6，Echo 为 GPIO13。
- 每 70 ms 触发一次，Trig 高电平约 10 μs，等待回波截止时间 45 ms。
- 距离换算：`distance_mm = pulse_us × 343 / 2000`。
- 20～4000 mm 为有效量程；小于 20 mm 为无效，超过 4000 mm 作为无返回。
- 使用最近 3 个样本的中值。相对历史跳变超过 150 mm 时，需要 2 个彼此相差不超过 80 mm 的
  新样本确认，首个跳变样本标为离群。
- Echo 一直为高、边沿次序异常等情况标为不确定；干净的低电平超时属于“空旷无回波”，不是近障。

避障层在使用滤波结果前先检查原始距离：原始回波 20～80 mm 立即判为 `NEAR`。有效且原始、
滤波距离都大于 80 mm 才属于明确 `CLEAR`。干净无回波、超过 4000 mm 和干净离群属于
`NO_ECHO`；高电平卡住或无效边沿属于 `UNCERTAIN`。

### 5.2 启动检查与正常巡线

上电进入 `SENSOR_CHECK`，必须连续获得 3 次明确空旷或干净无回波，才进入 `CLEAR`，检查期间
不驱动电机。当前 `bypass_enabled=true`。

正常巡线的 `CLEAR` 状态中，只有 `NEAR` 会立即中断巡线；其他超声波结果只用于诊断，不会因为
偶发无回波直接停车。虚拟 `1111` 在全部阶段都按普通线路处理，不触发 `FINISHED`。

### 5.3 绕障动作

当前顺序和参数如下：

| 状态 | 动作 | 持续时间/退出条件 |
| --- | --- | --- |
| `BRAKE` | 零命令刹停，暂停巡线内部状态 | 150 ms |
| `STRAFE_LEFT_DISTANCE` | 左横移 | 1468 ms（由1545 ms缩短5%并四舍五入） |
| `SETTLE_LEFT_TRIM` | 左移后零命令稳定，先消除侧滑 | 150 ms |
| `LEFT_HEADING_TRIM` | 车头向左微调，逆时针车体命令460 | 60 ms；轮命令 `-460 / +460 / +460` |
| `SETTLE_FORWARD` | 微调后零命令稳定 | 150 ms |
| `FORWARD_DISTANCE` | 前进 | 1184 ms（由1128 ms再增加5%并四舍五入） |
| `SETTLE_RIGHT` | 零命令稳定 | 150 ms |
| `STRAFE_RIGHT_DISTANCE` | 完整右横移，忽略线路 | 1097 ms；前400 ms线性缓升并衰减反向偏航补偿 |
| `POST_BYPASS_FORWARD` | 固定直行，忽略线路 | 525 ms；前150 ms为500，随后为400 |
| `FINISHED` | 锁存零输出 | 直到停止/复位 |

2026-09-01实车测试中，实验性的摄像头航向对齐只转动一次后流程进入锁存 `FAILSAFE`。按现场
要求，当前固件已彻底移除 `ALIGN_HEADING` 状态及其目标、阈值、脉冲和超时配置。检测到障碍后
识别近障并决定避障后只刹停150 ms，随后直接开始左移，不再执行入口车头左调。针对左移结束时
轮胎偶发打滑、车头略向右偏的问题，左移后先停150 ms，再以460命令逆时针微调60 ms，随后
再停150 ms才开始直行。该动作由上一版420/40 ms加强而来，是固定限时补偿，不读取摄像头，
也不会恢复已移除的航向对齐逻辑。

左横移稳态速度380、起步150 ms为500；前进稳态400、起步150 ms为500。右横移不再使用500的
起步增力，而是从可可靠驱动的车体指令300开始，在400 ms内线性增加到380。由于A/C轮第一拍
就被死区补偿钳到正负300，而B轮原本仅从460开始，实车出现了短暂向右偏航；现在同一400 ms内
叠加从-60线性衰减到0的逆时针车体指令，使B轮从约510缓升到570。最新实车观察发现左移
在-20%逆时针补偿实测中出现明显逆时针画圆，且B轮仅为-304、容易卡在静摩擦区。因此Kiwi逆解
改为给左移加入较温和的20%顺时针补偿，使B轮稳态提高到-456；右移仍使用50%的独立补偿，
并保留最小轮命令：

| 车体动作 | 稳态 A/B/C | 起步 A/B/C |
| --- | --- | --- |
| 左横移 | `-300 / -456 / +300` | `-333 / -600 / +333` |
| 前进 | `-400 / 0 / -400` | `-500 / 0 / -500` |
| 右横移 | `+300 / +570 / -300` | `+300 / +510 / -300`，中点约`+300 / +540 / -300`，400 ms缓升 |

近障进入 `BRAKE` 时巡线控制器被暂停，此后本轮不会恢复。右横移无论看到黑线、白底或 `1111`
都必须完成1097 ms，不再提前停车，也不再进入 `LINE_CONFIRM`。右移结束后立即进入
`POST_BYPASS_FORWARD`，使用固定直行命令前进525 ms，到时进入锁存 `FINISHED`。摄像头仍可输出
诊断数据，但不参与右移、最终直行或完成判定。

绕障动作期间连续 3 次 `UNCERTAIN` 会进入锁存的 `FAILSAFE`。前进或右横移阶段再次出现 `NEAR`
也会立即进入 `FAILSAFE`。`FINISHED` 和 `FAILSAFE` 都持续输出零，直到停止/复位。

### 6.2 电源和硬件连接注意事项

- 摄像头接 5V、GND、GPIO19 D-、GPIO20 D+。
- TFT 为 LQ_TFT18SPIV33 / ILI9163B，162×132、RGB565；接 3V3 和 GND，SPI2 8 MHz、Mode 0。
- 电机驱动板记录为 DA24/TB6615 一类双路 H 桥组合，逻辑电源用 3V3，电机电源独立，地线与
  ESP32 共地。板上准确丝印/芯片型号仍应在实车上复核。
- 当前现场记录称 HC-SR04 使用 3.3V 供电，Echo 直接进 GPIO13。另一份接线规划采用更常见的
  5V 供电方案；如果改为 5V，Echo **必须先分压或电平转换到 3.3V**，不可直接送入 ESP32。
  重新接线前应先核对实车当前供电，不能混用两套说明。
- 旧版 TFT 曾把 MOSI 写成 GPIO20；该接法与 USB 摄像头 D+ 冲突，已经作废。当前 MOSI 是 GPIO5。
- GPIO41/42 已给 C 轮编码器，不能再接旧计划中的 MPU6500；GPIO14 已给 B 轮 IN1，不能接旧计划
  中的 DHT11。当前主程序也没有启用 MPU6500 或 DHT11。

### 6.3 已退役的红外模块

旧 LQ-IR4CHV6 为低电平有效，曾使用：L/OUT4=GPIO5、LC/OUT3=GPIO4、RC/OUT2=GPIO2、
R/OUT1=GPIO1。现在红外驱动文件仍留在仓库作为历史接口，但没有编入当前主程序：

- GPIO5 已改为 TFT MOSI；
- GPIO1、GPIO2、GPIO4 当前未被主线功能占用；
- 不应按旧红外接线表接回后直接运行当前固件。

原生 USB 19/20 专用于摄像头，因此下载、监视和现场诊断走 CP210x UART0。主程序在收到串口 `u`
后先以115200 bit/s确认，再切换到460800 bit/s，以约5 FPS发送80×60 RGB332画面和原有状态记录；
画面包包含CRC32。`z` 退出预览并恢复115200，电脑端心跳中断3秒也会自动恢复。电脑运行
`tools/start_usb_camera_monitor.ps1` 即可打开窗口：红色覆盖为与小车判线阈值完全相同的黑线像素，
黄色为识别ROI，绿色和蓝色分别为近端、远端线路中心；右侧显示巡线、避障、超声波、电机与编码器
状态。窗口不会发送启动巡线的 `f`，关闭时会发送 `z`；红色按钮可随时发送 `x` 急停。
窗口检测到开发板复位或有效帧中断后，会自动等待固件回到常态115200并重新协商画面模式。正常重启
只按 RESET；若按住 BOOT 再释放 RESET 会进入ROM下载模式，此时主程序和摄像头画面都不会运行。

实验目录中的 `camera_wifi_preview` SoftAP 预览、UVC 枚举探针和单独流测试都是诊断固件，不属于
主程序；当前主程序不启动 Wi-Fi 预览。

## 8. 安全行为

- 初始化时先把电机方向、PWM 和 STBY/EN 置为安全状态。
- 最终命令为零时关闭 STBY；非零时先设置方向和 PWM，再打开 STBY。
- 电机反向前先清空对应 PWM，降低直接反转冲击。
- 上电默认 `IDLE`，无启动命令时不得转动。
- 巡线阶段摄像头过期、避障不确定、二次近障、计时终点和显式停车都能沿统一仲裁链输出零命令。
- 编码器当前用于诊断计数，不形成闭环速度控制。
