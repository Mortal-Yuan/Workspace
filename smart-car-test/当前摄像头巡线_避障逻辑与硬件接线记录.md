更新时间：2026-09-01

本文是对当前仓库源码、配置、测试、实验程序和项目日志的统一核对结果。它记录的是
`smart-car-test` 当前代码的实际行为，不把旧版红外巡线方案、已经撤回的调参方案或尚未完成的
硬件设想当成当前实现。

核对范围包括 `main/`、`test/host/`、三个 `experiments/`、构建配置、分区表、工作区设置以及项目内
全部一方文档；工作区中的课程资料、图片和压缩包用于硬件资料交叉核对。`build/` 生成物和

当作本项目控制逻辑逐行解释。

## 1. 当前状态先说明

- 当前主线已经从四路红外巡线改为 USB UVC 摄像头巡线；红外模块不参与主程序控制。
- 主控为 ESP32-S3-DevKitC-1，模组记录为 ESP32-S3-WROOM-2，使用 ESP-IDF 5.4.4。
- 运动底盘为三轮全向轮（Kiwi）结构：A 为右轮、B 为后轮、C 为左轮。
- 超声波检测到近障后，车辆执行“刹停 → 左横移 → 前进 → 右横移找线 → 静止确认
  → 摄像头巡线前进 1 秒 → FINISHED”；实验性的障碍前摄像头航向对齐已经撤销。
- 电机命令只有一个最终落点：控制器先完成模式、视觉、超声波和避障仲裁，再统一调用
  `motor_driver_apply()`。这样可以避免巡线和避障同时写电机。
- 当前 `build/smart-car-test.bin` 为 368784 字节（`0x5a090`），SHA-256 为
  `551F581933F3C33E5E65F0D00FBBDD6E082EBD20710A532A86A0B189A82DC26C`。
- 该镜像已通过主机回归和 ESP-IDF 5.4.4 构建，并于2026-09-01刷入确认过身份的ESP32-S3
  `COM3`。Flash三段哈希校验通过；随后无命令检查持续为 `IDLE`、A/B/C=0，摄像头
  `fresh=1` 且无丢帧或解码错误，超声波保持有效更新。

## 2. 主程序调用链

主入口和控制关系如下：

```text
app_main
  → app_controller_init
  → 20 ms 控制任务
      → ultrasonic_step                 采集超声波
      → camera_line_sensor_snapshot     读取最新视觉快照
      → start_button / UART             处理启动、停车和人工命令
      → 摄像头新鲜度与故障检查
      → obstacle_supervisor_step        仲裁避障、终点和故障
          ├─ BLOCK：输出零，保持停车
          ├─ LINE_FOLLOW：调用 line_follow_step
          └─ OVERRIDE：用 kiwi_kinematics_inverse 生成绕障动作
      → motor_driver_apply              唯一一次最终电机输出
```

控制模式包括 `IDLE`、`AUTONOMOUS`、`MANUAL`、`SELF_TEST` 和 `FAULT`。
自动模式中，摄像头快照超过 350 ms 没有更新会在同一控制周期进入 `FAULT` 并停车；该故障被标为
“本次开机不可恢复”。串口停车命令只会继续保持 `FAULT`，必须硬件复位或重新上电后再开始。

BOOT 键 GPIO0 是低有效启动键，带 50 ms 消抖、80 ms 释放重装和 500 ms 上电保护，只负责启动，
不作为停车键。板上的 RESET/EN 是硬件复位。串口 `f` 可启动，`x` 可停车；人工方向命令会退出
自动模式。

## 3. 摄像头采集与视觉算法

### 3.1 摄像头输入

- UVC 设备 VID:PID：`349c:3307`。
- 主程序固定请求 MJPEG 640×480 @ 15 FPS，流接口索引为 0。
- USB D- 接 GPIO19，D+ 接 GPIO20，摄像头供电为 5V 和 GND。
- 使用 3 个 512 KiB PSRAM 帧缓冲和 3 个 10 KiB URB；队列只保留一帧，来不及处理时丢弃旧工作，
  避免控制链堆积越来越迟。
- JPEG 解码为 RGB888，并按 1/8 缩放得到约 80×60 图像。
- 当前采用摄像头原生方向，`rotate_180=false`。

### 3.2 有效画面和二值化

解码后先只把下半幅交给视觉模块，再应用 ROI。换算到完整画面，当前主要分析区域为：

- 横向：25%～75%；
- 纵向：60%～93%；
- 对 80×60 解码图，约为 `x=20..59`、`y=36..55`，实际边界受整数取整和右开区间影响。

RGB 转灰度使用近似权重 `77R + 150G + 29B`。灰度直方图取第 2 百分位作为暗端、第 90 百分位
作为亮端；对比度小于 30 时，本帧仍是有效相机帧，但报告“未检测到线”。否则使用
`min(Otsu + 对比度/16, 120)` 作为黑色上限。小于等于阈值的像素才作为黑线，避免灰度不够低的
阴影被 Otsu 暗类误判成赛道黑线。

### 3.3 连通区域与线路几何

- 使用真正的二维八邻域 BFS 连通域。
- 当前普通线路没有最小面积、必须触底、最小高度、最大宽度、首次中心范围或历史最大跳变等
  硬门槛；只要连通区域非空就有资格成为候选。
- 没有可靠历史时选择面积最大的候选。
- 连续得到 3 帧普通线路后建立可靠历史；有历史时采用软评分：面积越大越好，近端中心和转向量
  越接近历史越好。它只降低偏离候选的分数，不硬拒绝急弯；画面只有一个候选时仍会接收。
- 宽终点形状不更新普通线路历史，避免终点污染下一帧的候选选择。

每个候选分别计算顶部三分之一的远端中心和底部三分之一的近端中心。中心位置按千分比缩放，
再加入 `-165` 的摄像头中心补偿。定义：

```text
heading = far_center - near_center
steering = near_center + 0.5 × heading
```

若近、远端跨越画面中心，并且 `|near| >= 160`、`|heading| >= 300`，判为发卡急弯，方向项增益
降为 0.1，防止远端黑线把近端转向过度拉偏。视觉内部限制到 ±2000，发布给控制器前限制到 ±1000。

新接受的普通线路会与上一份已发布快照平滑：中心值采用 `(2×旧值 + 新值)/3`，再重新计算转向。

### 3.4 虚拟四路巡线信号

为了复用原来的离散巡线控制，连续转向量被映射成四个虚拟传感器：

| 连续转向量 | 虚拟状态 | 含义 |
| ---: | :---: | --- |
| `< -600` | `1000` | L |
| `-600..-201` | `0100` | LC |
| `-200..200` | `0110` | LC + RC，居中 |
| `201..600` | `0010` | RC |
| `> 600` | `0001` | R |
| 无线路 | `0000` | 丢线 |
| 宽 T 形候选（运行时终点门禁关闭） | 按普通方向位输出 | 普通线路 |

代码保留了宽度至少占 ROI 800‰、面积至少占 200‰ 的 T 形候选分类和两帧确认能力，另有仅限
`IDLE` 使用的串口 `p` ASCII 摄像头视图。但当前自动运行始终关闭终点门禁，T 形、宽线和
`1111` 都按普通线路处理，不能触发停车。终点由绕障完成后的固定 1 秒巡线计时产生。

### 3.5 红色球识别（只观察）

同一张80×60 RGB888图会并行送入 `camera_ball_vision`。当前只启用红色类别，不参与巡线、避障或
电机仲裁。红色像素要求R通道至少45、比G/B较大者至少高8，并占RGB总量至少380‰；随后以八邻域
合并连通区域。候选连通域的平均R还必须比平均G/B较大者至少高40。候选球必须满足：面积至少占
整帧5‰、包围盒填充率至少350‰、短边/长边至少600‰，
且包围盒离四边至少2像素。球心移动不超过200‰的同色候选连续3帧后才置 `detected=1`。

串口 `BALL=color/candidate/detected/stable_frames` 中红色编号为2，并同时输出球心 `bxy`、尺寸
`bwh`、面积、填充率/圆度、置信度、平均RGB和颜色探针。2026-09-01真实红球首次测试连续确认到
稳定帧上限255，位置集中在 `x=-81..-84`、`y=714..717`，尺寸约87‰×133‰，区域平均RGB约
`160/97/90`，最红像素约 `210/93/80`。移走球后连续输出 `candidate=0/detected=0/stable=0`；重新
放回后约3帧恢复确认。返回过程还发现弱红背景均值约 `98/74/47` 偶尔抢占球心，现已用连通域平均
红色优势40过滤。修正版在红球存在时连续稳定于 `x=+41..+43`、`y=716..717`，不再跳向背景；
修正版烧录后再次移除红球，连续12秒保持 `BALL=2/0/0/0`，确认弱红背景不会成为候选。识别结果
目前仍不接入推球控制。

应用层默认速度上限为 400，可在 100～800 间调整。所有基础速度还会受该上限约束。

### 4.2 正常巡线

四路离散误差权重为 L=`-6`、LC=`-2`、RC=`+2`、R=`+6`，多个有效位取平均。方向改变必须连续
确认 3 次；确认前保留原方向，防止单帧噪声使车辆左右抖动。

有可靠连续转向且不处于反向保持时，差速修正按 `steering × 300 / 600` 计算并限制到 ±300；
否则使用离散误差乘 `Kp=120`。普通前进命令为：

```text
A = -base + correction
B = 0
C = -base - correction
```

也就是说当前接线下，正常直行是 A、C 同为负命令，B 为零。弯道和边缘情况下若命令过大，会
按比例缩到对应上限，而不是简单截断某一个轮。

只剩单个虚拟传感器时，对应内轮最低给 +100 的反转命令，帮助车头压入急弯。某个轮刚成为
主要驱动轮或发生换向，且目标绝对值达到 200 时，前 150 ms 至少给到绝对值 500，以克服静摩擦；
该增力不放大 +100 这类小内轮命令。

### 4.3 近端盲区与丢线搜索

- 新建立且 `|steering| >= 180` 的转向，会暂时保持上一份可靠巡线轨迹 180 ms；当转向回到
  80 以内释放。这用于黑线进入摄像头近端盲区时保持入弯动作。
- 若刚丢线且有可靠巡线历史，前 120 ms 沿用上一份未增力的巡线命令，之后停车到第 150 ms。
- 若开机就没有线或没有可靠历史，则完整 150 ms 都保持停车。
- 150 ms 后开始 A、C 反向的原地搜索，速度 211；每次开始或换向有 500/150 ms 增力。
- 搜索方向优先取已确认的离散方向，其次取最后一个绝对值至少 100 的连续转向，再取最后误差，
  最后默认向左。
- 搜索腿时长依次为 1.2、2.4、3.6、4.8、6.0、7.2 秒，之后一直以 7.2 秒左右交替；没有总超时停车。
- 看到第一个线路候选会在同一周期停止旋转；必须累计 3 个不同的相机解码帧仍检测到线，才恢复
  前进。重复使用同一相机帧不增加计数。

## 5. 超声波与绕障状态机

### 5.1 超声波测距

- HC-SR04 Trig 为 GPIO6，Echo 为 GPIO13。
- 每 70 ms 触发一次，Trig 高电平约 10 μs，等待回波截止时间 45 ms。
- 距离换算：`distance_mm = pulse_us × 343 / 2000`。
- 20～4000 mm 为有效量程；小于 20 mm 为无效，超过 4000 mm 作为无返回。
- 使用最近 3 个样本的中值。相对历史跳变超过 150 mm 时，需要 2 个彼此相差不超过 80 mm 的
  新样本确认，首个跳变样本标为离群。
- Echo 一直为高、边沿次序异常等情况标为不确定；干净的低电平超时属于“空旷无回波”，不是近障。

避障层在使用滤波结果前先检查原始距离：原始回波 20～60 mm 立即判为 `NEAR`。有效且原始、
滤波距离都大于 60 mm 才属于明确 `CLEAR`。干净无回波、超过 4000 mm 和干净离群属于
`NO_ECHO`；高电平卡住或无效边沿属于 `UNCERTAIN`。

### 5.2 启动检查与正常巡线

上电进入 `SENSOR_CHECK`，必须连续获得 3 次明确空旷或干净无回波，才进入 `CLEAR`，检查期间
不驱动电机。当前 `bypass_enabled=true`。

正常巡线的 `CLEAR` 状态中，只有 `NEAR` 会立即中断巡线；其他超声波结果只用于诊断，不会因为
偶发无回波直接停车。虚拟 `1111` 在全部阶段都按普通线路处理，不触发 `FINISHED`。

### 5.3 绕障动作

当前顺序和参数如下：

| 状态 | 动作 | 持续时间/退出条件 |
| --- | --- | --- |
| `BRAKE` | 零命令刹停，暂停巡线内部状态 | 150 ms |
| `STRAFE_LEFT_DISTANCE` | 左横移 | 1170 ms |
| `SETTLE_FORWARD` | 零命令稳定 | 150 ms |
| `FORWARD_DISTANCE` | 前进 | 1191 ms |
| `SETTLE_RIGHT` | 零命令稳定 | 150 ms |
| `STRAFE_RIGHT_DISTANCE` | 右横移并观察线路 | 最多 960 ms |
| `LINE_CONFIRM` | 静止确认线路 | 连续 5 个控制周期 |
| `POST_BYPASS_FORWARD` | 恢复摄像头巡线 | 1000 ms |
| `FINISHED` | 锁存零输出 | 直到停止/复位 |

2026-09-01实车测试中，实验性的摄像头航向对齐只转动一次后流程进入锁存 `FAILSAFE`。按现场
要求，当前固件已彻底移除 `ALIGN_HEADING` 状态及其目标、阈值、脉冲和超时配置。检测到障碍后
先刹停150 ms，随后直接开始左移；当前避障不再依据摄像头航向进行障碍前原地旋转。

横移稳态速度 380、起步 150 ms 为 500；前进稳态 400、起步 150 ms 为 500。Kiwi 逆解给左移
加入55%的顺时针补偿以修正轻微逆时针漂移，右移仍使用50%的独立补偿，并设置最小轮命令：

| 车体动作 | 稳态 A/B/C | 起步 A/B/C |
| --- | --- | --- |
| 左横移 | `-300 / -589 / +300` | `-300 / -775 / +300` |
| 前进 | `-400 / 0 / -400` | `-500 / 0 / -500` |
| 右横移 | `+300 / +570 / -300` | `+300 / +750 / -300` |

右横移期间一旦任何虚拟线路位非零，会在同一控制周期停止并进入 `LINE_CONFIRM`，初始确认数为 1。
累计 5 个 20 ms 控制周期仍见线后，标记绕障已完成并进入 `POST_BYPASS_FORWARD`。随后使用正常
摄像头转向巡线 1000 ms，到时进入锁存 `FINISHED`。这里确认的是控制周期，不是3个不同相机帧；
15 FPS 下同一相机帧可能被重复计数，这是与巡线重捕获不同的实现细节。

若右横移 960 ms 仍未看到线，或确认期间线路消失，当前源码会退出绕障并恢复巡线控制器，随后
使用其丢线搜索逻辑继续找线；**不会**像旧版 8 月 27 日方案那样直接进入 `FAILSAFE`。

绕障动作期间连续 3 次 `UNCERTAIN` 会进入锁存的 `FAILSAFE`。前进或右横移阶段再次出现 `NEAR`
也会立即进入 `FAILSAFE`。`FINISHED` 和 `FAILSAFE` 都持续输出零，直到停止/复位。

所有模块必须共地。GPIO7 建议外接约 10 kΩ 下拉，使复位、下载和 ROM 启动期间电机驱动保持关闭。

### 6.2 电源和硬件连接注意事项

- 摄像头接 5V、GND、GPIO19 D-、GPIO20 D+。
- TFT 为 LQ_TFT18SPIV33 / ILI9163B，162×132、RGB565；接 3V3 和 GND，SPI2 8 MHz、Mode 0。
- 电机驱动板记录为 DA24/TB6615 一类双路 H 桥组合，逻辑电源用 3V3，电机电源独立，地线与
  ESP32 共地。板上准确丝印/芯片型号仍应在实车上复核。
- 当前现场记录称 HC-SR04 使用 3.3V 供电，Echo 直接进 GPIO13。另一份接线规划采用更常见的
  5V 供电方案；如果改为 5V，Echo **必须先分压或电平转换到 3.3V**，不可直接送入 ESP32。
  重新接线前应先核对实车当前供电，不能混用两套说明。
- 旧版 TFT 曾把 MOSI 写成 GPIO20；该接法与 USB 摄像头 D+ 冲突，已经作废。当前 MOSI 是 GPIO5。
- GPIO41/42 已给 C 轮编码器，不能再接旧计划中的 MPU6500；GPIO14 已给 B 轮 IN1，不能接旧计划
  中的 DHT11。当前主程序也没有启用 MPU6500 或 DHT11。

### 6.3 已退役的红外模块

旧 LQ-IR4CHV6 为低电平有效，曾使用：L/OUT4=GPIO5、LC/OUT3=GPIO4、RC/OUT2=GPIO2、
R/OUT1=GPIO1。现在红外驱动文件仍留在仓库作为历史接口，但没有编入当前主程序：

- GPIO5 已改为 TFT MOSI；
- GPIO1、GPIO2、GPIO4 当前未被主线功能占用；
- 不应按旧红外接线表接回后直接运行当前固件。

## 8. 安全行为

- 初始化时先把电机方向、PWM 和 STBY/EN 置为安全状态。
- 最终命令为零时关闭 STBY；非零时先设置方向和 PWM，再打开 STBY。
- 电机反向前先清空对应 PWM，降低直接反转冲击。
- 上电默认 `IDLE`，无启动命令时不得转动。
- 摄像头过期、避障不确定、二次近障、计时终点和显式停车都能沿统一仲裁链输出零命令。
- 编码器当前用于诊断计数，不形成闭环速度控制。

## 10. 重新上车前检查清单

1. 核实 ESP32、驱动板、摄像头、屏幕、超声波和 CP210x 全部共地。
2. 核对摄像头 D-/D+ 为 GPIO19/20，TFT MOSI 为 GPIO5，不能按旧 GPIO20 接法。
3. 核实 HC-SR04 当前是 3.3V 直连方案还是 5V 分压方案；确认 Echo 到 GPIO13 不超过 3.3V。
4. 核实 A=右、B=后、C=左，以及编码器和电机方向线没有交叉。
5. 当前标定镜像已经刷入经身份确认的ESP32-S3 COM3；后续每次仍须先核实MAC
   `9c:cc:01:fb:8f:9c`，并确认上电保持 `IDLE`、A/B/C=0。
6. 车轮架空，确认近障刹停150 ms后不会原地旋转，而是直接输出左移起步命令。
7. 依次验证单轮、前进、1170 ms 左移、右移和急停，再落地低速测试。
8. 在现场确认软历史候选、急弯、丢线3个不同帧重捕获、60 mm近障、右移找线和最后1秒巡线停车。
9. 若屏幕影响 GPIO3/45 启动绑带电平，复核外接 10 kΩ 上拉/下拉。
